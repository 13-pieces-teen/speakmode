# 0.2.11 型号选择与默认模型升级验证

日期：2026-10-11。基线为 0.2.10 / 0.4.9，本版为 0.2.11 / 0.4.10。

用户明确要求更换默认模型，因此将默认整理模型改为 `qwen3.8-flash`，保留可选型号。此决定不回改上一版模型比较成绩，不等于新提示已经通过预留验证；`AUTOMATIC_PROTOCOL_PROMOTED=false`，实际请求依旧使用原 `mode-contract-v1` 和关闭思考设置。

## 功能变化

- 云端服务里的“整理模型”移到配置表首位，显示具体型号 ID；当前选择尚未保存时标注状态，顶部单独显示已保存型号。
- 默认项为 Qwen 3.8 Flash，也可选 Flash、Plus、3.7 Plus 及其 2026-05-26 快照；不展示未经测量的质量分数或速度承诺。
- 保存仍走原生 `provider.configure`、SQLite 版本检查及快照刷新，当前录音配置已在会话开始冻结。语音识别型号与文本整理型号独立。
- 启动时仅一次将旧北京 Flash 配置切到 3.8 Flash，其他已有型号和地域保持。事务同步写 SQL/JSON 版本和升级标记；之后用户手动选回 Flash 不会被再次覆盖。
- Key 的索引由 provider/地域/业务空间决定，不依赖模型，因此同一账号配置切型号不需要重新保存 Key。
- 复审发现并修复：配置提交成功但完整快照刷新失败时，下一次录音可能继续使用旧配置。现在先发布提交成功的 ProviderConfig 回执，再尝试全量刷新。新增隔离 SQLite 故障注入覆盖配置、SQL/JSON 版本、会话缓存、冲突/SQL 失败以及恢复/重启；不扩展其他设置的缓存行为。
