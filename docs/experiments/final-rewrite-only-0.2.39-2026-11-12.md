# 0.2.39：最终成稿的完成与恢复契约

## 问题与行为

此前主整理与自动恢复均失败后，会把仅通过内容检查的未润色草稿或本地基础清理稿保存为 ready，计数并尝试输入。现在只有完整整理管线成功，才保存成稿并进入一次性交付；失败明确显示“最终整理未完成”，保留识别稿和重试入口，不保存中间成稿、不计入完成量、不自动输入。

重新审查后还修复了以下路径：

- 初次、重试和历史长文整理统一按完整正文 Unicode 字符数分配预算：800 字以内 20 秒、801–3000 字 30 秒、其余 60 秒。此前重试和历史整理始终只有 20 秒。
- 重试整理、重试识别后的整理和来源保存重试也允许执行一次独立自动整理恢复；恢复使用通用自动场合，保留完整原稿、冻结词典和输出语言。预算分别为 30、60、120 秒。重试成功只供查看，不能恢复原来的自动输入资格。
- 未完成最终整理且没有成稿时，开始下一条录音会提示先重试、显式采用识别稿或放弃，防止替换唯一的活动恢复入口；保留历史关闭时也适用。不增加跨重启的未完成内容保留，不绕过原有隐私设置。
- “重试整理”直接出现在恢复面板，无需展开“更多恢复方式”。
- 删除仅通过内容检查的草稿缓存和取用入口；本地基础清理模块仅参与历史算法测试，不编译到产品恢复路径。
- 主失败原因和自动恢复错误独立记录；全部失败的诊断结论为 Failed。取消、会话替换、来源校验、保存冲突与撤销交付许可的原有约束保持有效。
- 显式采用识别稿、手动编辑与旧历史来源标记继续按用户操作处理，不把旧基础稿改名为最终成稿。

## 验证

- Windows 桌面完整 Rust 库回归：1097 passed、0 failed、4 ignored。针对旧基础稿交付契约的测试已替换，另移除不再存在的草稿缓存测试；数量不能直接当作覆盖度比较。
- 真实本机 HTTP 生成与完整复核、主失败后的恢复、超过旧 5 秒截止的复核、含义风险拒绝、润色失败、超时、取消与会话替换均有覆盖。
- 新增回归验证重试自动恢复成功也不会自动输入；最终成稿保存失败可只重试保存且只计数一次；未完成原稿不能被新录音替换，显式放弃后可开始下一条，覆盖开启和关闭历史。
- TypeScript、前端生产构建和输入反馈 helper 通过；helper 验证恢复面板的重试按钮无需展开且只发送带会话身份的重试命令。
- 验证日志为本地 `.validation/final-rewrite-audit-tests-r2.log`、`.validation/final-rewrite-audit-frontend.log` 与 `.validation/final-rewrite-audit-ui.json`。
- Windows 安装包构建单独记录于 `.validation/final-rewrite-audit-package.log`。

这些验证使用合成来源、本机 HTTP、隔离 SQLite 和前端组件替身。真实麦克风、真实云端长语音、目标应用输入与安装升级未验收。服务持续不可用时可能无法完成最终成稿，但基础稿不会冒充成功。扩大预算可能增加异常路径等待时间，取消仍可终止等待。
