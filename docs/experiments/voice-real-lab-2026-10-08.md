# SpeakMode 0.1.5 真实服务与 Windows 采音实验

日期：2026-10-08。被评估的产品基线为 `0.1.5`，生产代码提交为 `c192ea08f17a1756e8ce7892cad2d7dd841e7953`。本轮新增实验工具与报告，未修改 ASR、整理、采音或交付的产品实现，也没有发布已修复的新版本。

本轮确实调用了真实百炼服务，并使用了本机 WASAPI 设备及 Windows 原生输入控件。三个实验分别验证云端模块、采音模块和受控交付模块，尚未验证用户真实口述的完整桌面任务。

实际服务配置为百炼北京地域，ASR `qwen3-asr-flash-realtime`，整理 `qwen-flash`，适配器 `qwen-realtime-v1`。工具调用生产 `asr::run` 与 `rewrite::rewrite`。原生工具在内部使用应用已配置凭据，Key 不写入实验 JSON、日志或报告；配置读取限定到服务配置，不读取用户正文。实验不修改真实词典、偏好或历史。

评分规则如下：

- **CER**：NFKC、casefold，去 Unicode 标点和空白后，字符 Levenshtein 距离除以参考字符数。没有拼写修复、数字归一化或事后参考答案修改。
- **词条命中**：在原始识别文本 casefold 后查找完整词条字符串。`speak mode` 不算 `SpeakMode`，`super whisper` 不算 `Superwhisper`，中文音译不算英文词条。它与去空白的 CER 是两个不同指标。
- **B 语义**：下周开发范围；最终预算三千五百且明确不是五千；时间未确认的条件；先不要发送邀请；周五试用仍可能、时间未确定。只有成功生产输出才有可交付成稿评分；额外诊断结果另列。
- **C 语义**：预登记检查静音后保存结果到本地及末句不要删除原始录音；人工同时确认第一项先检查麦克风仍保留。人工检查不改变 CER。
- **附加人工复核**：回看 A 的“今天”和技术名是否保留。“今天”遗漏是额外发现，不是事后更换词条或 CER 评分条件。

语义复核由主执行代理与独立只读代理对固定正文逐项完成，记录在 `manual-review.json`；不是人类被试研究或独立人类标注。

预登记停止条件为凭据/配额/权限错误停止；连续三次传输错误停止剩余请求；不自动重试、不重生成固定输入。所有注册请求均已执行，没有触发停止条件。实际云端墙钟为 378.841 秒，2026-10-08 北京时间 10:55:49 至 11:02:08；不把这一墙钟值当作用户任务完成时延。

## 来源覆盖失败的额外诊断

为定位拒绝原因，在 r1 结束后使用冻结的 `B-off-r1` 来源又发出 **2 次新整理请求**，轻/结构各一次，登记在 `diagnostic-preregistration.json`。它们不是 r1 自动重试，不替换原来 8/8 拒绝记录，也不是修复版本的对比结果。请求正文仍为原生产 `rewrite::request_body`，只对这份已知合成来源保留新响应的 `message.content`。

## 本机采音与停止清理

`capture_lab` 使用真实默认麦克风，播放固定 A/C WAV，执行短→长→短→长→短五轮。调用生产 `CaptureHandle`，覆盖回调缓存池、单声道混音、Rubato 重采样、100 ms PCM16 输出、停止接纳、尾帧排空和资源释放。捕获 PCM 只在内存中汇总，不保存、不上传；不调用识别或整理，也不修改系统音频设备设置。

五轮默认输入采样率均为 48 kHz。五轮源采样合计 5,591,520 个、**116.490 秒**，墙钟 **117.985 秒**，输出 1,169 帧及 2,092 个 level 事件。采样时长包含静音和实验的前后等待；不能解释成真人说话时长。level 事件说明模块发出了能量数据，未验证悬浮栏实际动画或声音语义。

五轮都满足：`complete=true`、非取消、收到首次样本、捕获错误为空；帧数与 summary 匹配；序号错误和畸形帧均为 0；排空到通道断开；资源释放为真；汇总 PCM 削波样本为 0。停止清理范围为 61.035–76.757 ms。首样本由回调接受时间计量，不等于字幕出现时间。

工具在运行前定义的声学信号启发式要求：播放阶段 RMS **大于 0.0025，且大于该轮 baseline RMS 的 1.5 倍**。只有第五轮同时满足，前四轮低于绝对阈值。RMS 相位按消费者取帧阶段划分，缓冲和声学延迟可能跨越阶段边界。

因此只能确认采集链路在这五轮持续运行并完整结束，**不能声称五轮均录到了固定句、没有环境声，或这些录回信号能准确识别**。即使第五轮信号增加，也只是聚合声学观察，不证明具体词句来自播放音频。没有运行旧版本同设备对照，亦未进行设备切换、断连、睡眠/恢复、多小时运行或麦克风/驱动故障测试；不能报告“稳定性提升 X%”或“已无丢音”。

两个可写控件都只发出一次四事件粘贴组合，同一 permit 的重复粘贴被 `attemptConsumed` 拒绝。生产 `DispatchReceipt` 仍为 **Unconfirmed**；只有本实验对自有控件进行已知合成文本读回后确认插入。实验构造受控 permit，未验证真实会话的 SQLite 交付账本和整个协调器，不能把 8/8 扩大为用户任意软件、真实右 Alt 或所有输入位置的验收。

## 下一版本建议与验收方向（尚未实施）

1. **优先处理来源映射表达。** 保留不可变 ASR 来源、完整审计和严格覆盖要求，实验模型请求中用短别名（如 `s0`…`s9`）代替长 UUID+provider ID，由冻结映射表还原真实身份；未知、重复、缺失别名仍拒绝。进一步让删除口语冗余和自我纠正来源显式归属到正确输出，避免模型只引用留下的文字。不是在响应后猜测补齐 `sourceRefs`，也不是放宽覆盖校验。应注册新候选版本，使用同一音频矩阵及更多碎片语料测量可交付率、完整审计和错误引用，原 r1 失败记录不覆盖。
2. **独立检查时间、条件和否定。** 当前覆盖检查没有发现“今天”遗漏。可从冻结 ASR 提取限定条件用于结果风险检测，缺失或无法确认时标示对照/恢复入口；保留词义及作用范围，不自动编造补回文本。先以“今天/下周/可能/如果/不要/不是”及归属范围回归案例验证，再评估误报和漏报。关键词存在本身仍不是语义保真的证明。
3. **先验证声学实验条件，再评估采音增量。** 当前四轮信号低于预定义绝对阈值。下一次先确认播放设备、音量、麦克风方向与可观测信号，再冻结设置；不要把本次弱信号结果事后换阈值改成通过。用旧/新版本相同设备与音频做采音对照，并加入真实录音的重复启动、长停顿、即刻结束尾词和异常恢复。没有这些结果前，不给稳定性增益百分比。
4. **另做实际桌面任务验收。** 云端注入、硬件采音和原生控件实验目前分开。后续需实际桌面程序的热键→录音→字幕→整理→保存→交付连续运行，并在用户指定目标核验光标和文字结果。真实 ASR、渲染、账本和宿主插入应分别有证据，不用本轮模块结果替代。

本报告完成的是缺口定位和下一步实验建议。短 ID、映射契约优化、条件 guard、声学对照和桌面完整任务验收都尚未实施或通过验证。

## 结论边界

词典对本次固定专有词语料有清楚、可复现的局部效果；采音在五轮真实设备运行中完成缓冲、停止和清理，但声学强度不足以认定五轮全部采到了指定语句。整理是本轮最明确的优先问题：一半请求被来源覆盖检查拒绝，且两个通过的结构输出丢失时间限定。

这些证据来自固定 TTS、真实服务请求及受控本机模块实验，尚未包括真人语音准确率、实际右 Alt、悬浮字幕光学可见性、SQLite 会话/交付账本、真实宿主应用插入和整条用户任务。没有旧版本同条件硬件对照，不能声称本次实验已经证明 0.1.5 的采音稳定性提升，更不能将受控测试通过率外推成生产可靠性。
