## 已实现的使用流程

侧栏“个性化” → 添加身份或只设置表达习惯 → 选择作用场合 → 启用并保存 → 选择同一段口述进行基础／画像对照 → 查看实际参考与差异 → 明确评价。

- 最多 3 个可编辑身份；职业、领域、工作描述、任务、沟通对象和补充要求分开保存。
- 通用表达习惯与场合覆盖；模板建议需明确接受，日常聊天默认不带职业背景。
- 使用现有词典和语言设置；日期展示现有规范，不伪造独立格式选项。
- 保存失败保留草稿；版本冲突展示最新设置；未保存内容有导航保护。
- 录音、重试、历史候选、确认纠错和预览使用冻结画像；生成／复核／修复共同参考同一快照。
- 两组试写共享源文、模式、语言、词典和供应商配置。每组使用原有整理预算，失败独立呈现，不自动输入外部应用。
- 停用或删除取消相关未完成任务，拒绝迟到交付；保留原始识别稿。
- 输出正文保持不可变，画像详情单独存储；删除身份物理清除对应参考详情并阻止旧身份 ID 复活。
- 本地统计按任务去重；预览与普通整理分开；只有有效对照的显式评价进入评价分母。不展示无定义的个性化程度分数。

## 本轮发现并修复的问题

1. 新增画像全链路测试发现，原有 admission 排除一般 scalar 数值时，无单位“预算三千”可能被错误改为“预算999”，即使复核模型给出全通过也无法确定性拦截。新增有限的显式金额标签识别，保留三千→3000及明确改口，拒绝金额改变／删除／新增。普通数字、列表编号、代码和逐字引用不因此升级为金额。
2. 重放完成事件可能覆盖用户已保存的显式评价。完成事件现保留已有评价，显式改评价仍可生效；取消对照会退出有效评价分母。
3. 历史确认纠错的本次语言选择原先可能与 receipt 不一致，现统一冻结后传给生成与回执。
4. 试写期间可以立即停用画像，前后端均拒绝取消后迟到的成功结果。
5. 三阶段除校验实际请求内容，还校验本地画像版本，即使两个版本传给模型的文字相同，也不能交叉使用回执。金额标签识别只检查就近有界窗口，避免长文中每个数字重复复制整段前文。

金额守卫仍是有限数值检查，不证明金额归属或一般语义保真，也不覆盖无单位的英文拼写数词。职业背景不能替代原始内容和独立复核。

## 2026-10-24：邮件正文与复核回归

用户确认邮件应直接成稿，省去明确面向助手的起草包装，同时保留具体材料、客户问题、收件人请求、条件和承诺。`situational-dictation-v4` 将这项固定合同传给生成、复核和有界局部修复；显式其他场合优先于 Email 宿主提示，原始识别与来源 ID 不修改。画像不能扩大省略范围，不能补写问题答案、收件人或署名。

固定文本开发实验暴露了等义否定的误拦。新增有限拼写 `暂无 / 尚无 / 无明确 / 而非`，保护 `无法` 最长匹配、真实问题与字面量，排除若干完整词的跨词误识别；没有通用“无”或类别／作用域豁免。四份实际误拦候选现在可进入独立复核，真实问题／引语丢失仍被拒绝。该有限分类不证明语义等价，复杂格式式或疑问式起草包装仍可能回退。

三轮开发结果分别为 16 路径 26 请求（8 接受）、16 路径 31 请求（13 接受）、单个冲突画像案例 4 路径 8 请求（3 接受）。最后一轮四份正文相同，D 仍被模型误拒，不能宣称个人表达合同 v2 已解决复核误拒，也不能合并不同轮次为质量通过率。当前 999 项 library 和 10 项消融工具测试通过；真实录音与用户采纳仍为 NOT_RUN。逐条证据见 [邮件实验](personalization-email-body-2026-10-24.md)。

另一个 24 请求的逐单元核对实验与基线判定相同，却更慢；只保留显式实验入口，不接入生产选择。见 [覆盖复核实验](personalization-coverage-review-2026-10-24.md)。本轮继续保持 Draft，不按模型接受数宣布整理质量已验收。

## 接下来的验收

依照 PRD 固定相同源文和服务配置，分别比较基础整理、仅职业、完整画像和移除全部职业信息的习惯配置。先确认小批结果符合保真与调用预算，再扩大到冻结的独立材料；同时记录负例、失败、原文回退与取消，不能只保留成功样本。

真实任务需由用户确认什么算可用成稿，记录从停止录音到可用的时间和编辑量。至少分别报告“画像被参考”“明确偏好被执行”“用户认为更好”，不将三者合并为一个个性化分数。
