# SpeakMode 0.2.4：模式试用与候选对照验证

2026-10-09。基线 `5d5047c`（0.2.3），分支 `feat/mode-quality-0.2.4`。实施范围见 [计划](../plans/mode-0.2.4.md)。本机证据目录：`D:/Codex_Project/SpeakMode_Dev/evidence/mode-0.2.4-2026-10-09-r1`。

## 已完成的工程增量

历史试用按 session/source revision 只读获取完整 SourceRevision，不再将识别分片拼成一条。分片 ID、顺序、时间与正文保持；请求前后核对来源，拒绝过期、删除或无效来源。自由文本按显式换行构造合成片段，界面标明与真实 ASR 分片的区别。

编辑器新增“对比轻整理与结构”，同一输入、模型快照、运行身份、取消令牌与工作租约下串行两次请求。比较独立于未保存的个人规则，无须先给 Mode 命名。任何一侧失败都不展示半份新比较；不写入历史、不改变默认模式、不自动输入。原来的个人 Mode 试用仍是单次请求。

历史新候选可对照“生成前文本”。比较基线在生成时冻结，其他版本变化不会悄悄替换左栏；过期候选不能采用。字符差异只用于显示；局部恢复仍依赖用户选择、来源 ID 与原生版本检查。长文本超出精细差异预算时显示完整内容与整体标色说明。

## 工程验证与真实发现

首轮 Rust 全库 **481 passed / 1 failed / 3 ignored**。固定参考中的“会议地点在图书馆，还没确认”被旧限定检查误拦：逗号切句丢失了待确认尾句的主语。新增有限规则只允许逗号紧邻、无独立主语的 Pending 尾句继承上一小句作用域；不跨句号、换行或项目，不放宽其他条件或否定。固定语料及参考未修改，正反例覆盖错主体与单字代词。

修复后全库 **484 passed / 0 failed / 3 ignored**；实验工具另 3 项离线测试通过。新增 12 项 preview 测试覆盖来源保留、容量、歧义 payload、真实数据库版本检查、双次串行／单次个人试用、取消与工作租约、失败不返回部分结果。

TypeScript/Vite 通过；字符差异 6 项、局部恢复组件/helper 11 项通过。Mode 浏览器首轮 9/11：两个窄屏检查把 Radix 的透明且不接收事件的原生 radio 输入当作可见溢出。验收工具保留原始测量，仅豁免精确匹配的隐藏 radio；产品 CSS 未因该误报改动。最终 Mode 浏览器 **11/11**、既有 UI **14/14**，均无页面错误或外部请求。Mode 覆盖 1440/1024/720/430 宽度、历史只读与显式转换、取消与迟到响应、失败保留、离开、候选冻结基线／过期和差异退化。浏览器使用合成 bridge，不代替原生云端或用户数据验证。

## 首轮真实云端诊断：接口全通过，但质量门槛未通过

使用当前配置 `qwen-flash` / 百炼北京，4 条人工开发输入 × light/structure/auto × 旧／新提示共 **24 次**，无重试。每对只有 system 提示不同，SourceItems、模型与请求参数相同；交错旧／新先后，调用前持久化完整计划。两个实验臂共同使用修复后的当前解析器，因此这是提示对比，不是旧 0.2.3 二进制端到端基准。只读 provider_config，不查询个人历史正文；密钥只由原生凭据接口读取，不进入收据。

24/24 返回完整且被解析器接受。逐内容复核仍发现：

- 新结构稿在短反馈中删掉“我刚看完页面”，也削弱了“我觉得”的判断归属；旧稿同样对主观归属保留不足。
- 旧／新轻整理都把主题来回补充归并了，未遵守本轮目标中的叙述顺序。
- 旧／新自动模式在主题回返案例均选 light，并继续归并，未达到标注的结构选择。
- 新轻整理／自动在条件案例用逗号串起独立建议，产生条件作用范围不清的问题。
- 新结构稿的主题回返案例避免了旧稿补出的“原定／仍需核实”，这是局部改善，不能抵消其他失败。

因此 **mode-contract-v2 未达到整理质量门槛**。原始 `paired-cloud-r1.json` / `.jsonl` 及逐输出 agent 复核保留；解析通过不称作事实保留通过，人工开发集不称作冻结留出或真人研究。

## 第二轮复测与默认规则决策

`mode-contract-v3` 明确保留观察行为与主观归属、轻整理的后置补充顺序、单对象连续反馈、自动识别主题回返，以及条件句的断句边界。未修改固定输入、保留要求、人工参考或模型。另行预登记同样 24 次旧／新配对，保留于 `paired-cloud-r2.json` / `.jsonl`；两个运行合计 48 次，不用第二轮覆盖第一轮。

第二轮仍 24/24 解析通过。条件案例的 light/auto 恢复句号边界；但新结构稿依旧删掉已查看页面的行为和主观归属，Light 依旧重排主题，Auto 主题案例依旧选择 light。因此 **v3 仍未达成进入默认版本的门槛**。旧基线也有遗漏和错选，并不因保留它而被宣称质量合格。

最终普通口述、个人试用与双模式比较使用与 0.2.3 相同的原有提示 `mode-contract-v1`。v3 通过独立 `experimental_request_body` 保留给显式实验工具；正常请求不能误用该候选。本版的实证收益是来源保留、可审阅比较与有限误拦修复，不宣称整体整理质量或用户效率提升。

本轮由 Codex/子 Agent 按固定要求复核具体输出，非盲、非独立真人评测。四条开发输入只有每条件一次请求，不据其延迟变化推断提速，不提供总体准确率。其余 12 条开发输入只做离线协议检查，尚未调用云端；真实人声、ASR 和端到端插入不在本轮实验内。
