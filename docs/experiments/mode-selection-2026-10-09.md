# Mode 方案实测与最终选择

2026-10-09。生产基线 `55a5b3b`。实验结束：20 条新合成输入、240 次真实百炼请求、无网络失败或自动重试。

**选择：以 `typed-flash`（一次生成编辑单元＋组织方案，再由本地渲染）作为下一阶段实现路线。日常生产默认仍保留 `baseline-flash`。** 候选在确认集的完整任务通过数最多，但出现 3 次已被校验放行的否定作用域错误，未达到预注册的切换门槛。不得将研究候选直接称为已经安全发布的升级。

## 怎么比较

- [预注册](mode-selection-2026-10-09-plan.md)在新云端调用前保存：筛选 8 条 × 3 Mode × 4 臂；确认 12 条 × 3 Mode × 2 臂 × 2 次重复。重复不是独立语料。
- [语料](fixtures/mode-quality-v2.json)由独立 Agent 编写，候选作者没有读取它；语料作者没有读取新提示词。确认集包含无标点、跨分片和较长口述。
- 使用相同地区、输入、个人规则、temperature=0.2、非思考、20 秒上限；保留每次原始响应、token、请求体及文件 SHA。筛选后没有修改候选、语料或验收标准。
- 两个 Agent 隐藏 arm/model 标签后复核，完全相同的同案例同模式输出复用同一判断，再映射回每次请求。共复核筛选 55 份、确认 58 份不同的已接受输出；边界判断另行复核。这不是人类盲评或用户研究。
- 完整任务通过 = 协议与本地检查接受 ＋ 信息保真 ＋ Mode 组织要求 ＋ 兼容个人规则 ＋ 合理 Auto 路由。拒绝与失败留在全部请求分母。
- 语义错误数字只描述被接受输出；被拒绝原始响应单独做诊断，不能把拒绝都视为正确拦截，也不能把它们算成成功交付。

| 方案 | 协议接受 | 完整任务通过 | P50 | P95 | 输入＋输出 token |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原版 Flash | 20/24 | 12/24（50.0%） | 1.160 秒 | 1.858 秒 | 28,111 |
| 简洁合同＋对照例子 / Flash | 21/24 | 13/24（54.2%） | 1.055 秒 | 1.294 秒 | 27,124 |
| 编辑单元＋本地排版 / Flash | 24/24 | 17/24（70.8%） | 1.556 秒 | 1.830 秒 | 41,663 |
| 同一编辑单元协议 / Plus | 23/24 | 17/24（70.8%） | 3.424 秒 | 3.793 秒 | 41,642 |

按预注册顺序选择 typed-flash 进入确认：与 typed-plus 同为 17 个任务通过，但已接受且保真的输出为 24 对 23；本次 Plus 没有显示额外质量收益。不能据此断言 Plus 在所有任务上更差。

这里发现 7 次原有 guard 误拦和 1 次真实 typed 布局冲突。尤其六份正确消解“十二份→十五份”的文本被误拦；typed 的对应稿保留了旧数字及后面的改口过程，因而通过。此项接受率收益不是改口质量提升。冻结语料允许保留明确的更正过程，不能事后收紧要求改变得分；产品想要干净最终稿仍有未满足之处。

| 指标 | 原版 Flash | 编辑单元＋本地排版 / Flash |
| --- | ---: | ---: |
| 协议接受 | 37/72 | 57/72 |
| 完整任务通过 | 22/72（30.6%） | 34/72（47.2%） |
| Light 任务通过 | 11/24 | 16/24 |
| Structure 任务通过 | 7/24 | 12/24 |
| Auto 任务通过 | 4/24 | 6/24 |
| 已接受输出中语义通过 | 35/37 | 54/57 |
| 已接受输出中关键语义错误 | 0 | 3 |
| P50 | 1.528 秒 | 2.005 秒 |
| P95 | 2.534 秒 | 2.586 秒 |
| 输入＋输出 token | 87,215 | 128,290 |

在相同案例/Mode/重复的 72 对结果中，候选任务通过而基线失败 12 对，反向 0 对，其余 60 对相同。这说明本次任务完成有增量；不代表失败对里候选的错误更安全。基线通常拒绝结果，候选有时放行错误文本，两者都算任务失败却有不同后果。

任务通过增加 **16.7 个百分点**；P50 增加约 **0.48 秒**。时间包含调用前实验记录持久化、云端响应和解析，不含录音、ASR、UI 或真正插入，不能称为 stop-to-paste 延迟。全实验共 354,045 token；未把 token 数当成实付账单。

这些专门覆盖风险边界的合成案例，不代表日常听写准确率或用户使用分布。只做两次重复，未提供统计显著性、整体稳定性或对 Typeless 的优势结论。

## 为什么没有切换默认

确认输入被故意分成无标点片段，连读含义是：

> 演示从九点半开始，不是说九点半签到，签到还是九点。

typed 的已接受输出出现：

> 那个演示从九点半开始不是。说九点半签到，签到还是九点。

`不是说` 被拆开，否定的对象出现实质歧义。此错误出现在两次 Auto 和一次 Structure，共 3 次，均来自同一独立案例。不能说是 3 类独立错误，也不能说一定把数值直接改成另一个值；错误是可产生错误读法的否定作用域破坏。另一名 Agent 复核维持该判断。

基线已接受输出的两次语义失败则是将“间隔先用 25 秒”写成“设为 25 秒”，丢掉冻结要求中的暂定性质。基线的被拒绝输出还包含一些真实错误，因此保留基线不等于认定其整体质量合格。

预注册要求候选无关键错误、完整任务通过率至少 95%、各 Mode 不退化、较基线提升至少 10 个百分点，并通过生产恢复兼容检查。候选只满足部分增量条件，**发布门槛失败**，机器可读的 `finalRecommendation` 为 `baseline-flash`。

## 已定位的工程问题与下一步取舍

1. **先修校验器的错误语义单元。** `我说错了` 有时撤销紧邻的地点句而不是指向更早的日期；`能不能提交` 被当成禁止；跨 ASR 分片的否定被绑定到错误动作。应保留不可变来源，同时建立跨分片分析范围和明确更正目标，分别测误拦与漏拦，不能简单关闭 guard。
2. **保留 typed 路线，但先解决跨片段修句。** 本地排序只能约束声明的来源，不能保证 unit 是完整意思。`不是` 不应被独立断句，条件也不能被复制成无条件指令。必须在渲染前验证单元边界与限定关系；原始全文仍需供模型参考。
3. **Auto 与个人规则仍是弱项。** 确认 Auto 仅 6/24，直接口吻转换等个人规则仍被忽略。应将可明确执行的格式偏好与内容编辑分开，单独验证路由与实际组织结果。
4. **暂不为 Plus 付出额外等待。** 本轮筛选未见收益，继续以 Flash 做工程修复；更广模型评估和风险触发的第二次审核尚未运行，不能宣称其无效。

typed 目前把渲染稿适配为一个全来源父块。上线前还需单独处理历史来源、逐句恢复、候选采用与撤销的兼容性；不能直接把这个实验解析器接到生产默认。

本轮没有修改日常 prompt、模型设置、数据库或桌面安装包。旧版仍可正常使用；实验最佳路线与可发布默认是两个明确的决策。
