# 0.2.14：口语停顿清理的误回退修复

日期：2026-10-11。前版桌面 0.2.13 / 前端 0.4.12，本版桌面 0.2.14 / 前端 0.4.13。

## 结论与原因

这次用户提供的短口述确实被退回完整识别稿。只读验证运行进程版本、发布产物哈希，以及最新来源与用户提供文本的标点/空白无关匹配；该条记录为 `rewriteFallback=meaningRisk`，没有超时。数据库不保留当时被拒绝的模型文本，因此只能确认原使用过程发生了校验回退，不能声称还原了当时的具体响应。

本轮另用用户主动提供的原文执行两次真实文字整理：生产 `mode-contract-v1` 与已有实验 `natural-cleanup-v2` 各一次，型号均为北京地域 `qwen3.8-flash`。两份输出都清理了停顿词与断句重复，独立 Agent 隐藏实验身份复核后，均在信息保真、清理、可读性、语气和专名五维通过，没有标记关键语义错误。原稿的清理和可读性未通过。

但发布版 0.2.13 数量校验把口语中的三个“一个”都当成必须保留的数量，两份生成结果均被拒绝并模拟退回原稿。这解释了复现中“模型已经整理，最终交付仍有语气词”的落差。

## 实施增量

- 新增有限的描述性属性构式检查：相邻暂停中的名词短语重启、所属对象的效果，以及带明确修饰的实际情况/状态/表现。检查完整名词，排除“效果图、状态机、情况说明”。
- 豁免数量时，同时要求候选保留对应来源、所属对象和局部观察/比较动作。不能借用别处出现的对象名，不允许任意并列前缀绕过动作检查，也不能把对象名称内部的“测试”剥成动作。
- 保留真实数量、仅/只/每次、后续数量对比、另一对象、选择/创建/删除/切换及引用/代码边界。裸“一个状态”等歧义数量不作新豁免。
- 单独记录新守卫模块的编译指纹；评分器兼容完整旧五键与新六键收据，拒绝缺失基础键、未知键或无效哈希。

这次没有更换提示词或模型，没有增加云请求次数或等待预算。原始来源、完整原稿回退、保存校验、一次性输入与安静完成的流程保持原实现。新规则只影响候选是否被有限校验接受，不直接改写正文。

正文与私有结果留在仓库外 `output/validation/filler-delivery-0.2.14/`；公开仓库只保存匿名合成测试与统计，不复制个人历史正文、Key、配置或录音。旧版 68 个请求的复验只用于回归检查，不作为新的独立预留集。本轮没有实现本地机械清理，完整原稿仍为兜底。
