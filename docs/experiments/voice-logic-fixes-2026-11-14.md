## 处理中复制的完整接管

识别收尾或整理过程中，主面板和录音浮层都允许显式复制已有文字。复制成功才撤销这条口述的自动输入并切为 Preview，整理任务继续；复制失败不改变许可。避免用户按提示手动粘贴后，晚到的成稿又自动输入。

主面板的取消/复制使用独立短操作锁，不被尚未结束的云重试阻塞。浮层不在处理中提供尚未就绪的“查看结果”导航。成功后的提示明确本次不再自动输入，成稿需手动复制。

测试覆盖 main/recorder × FinalizingAsr/Rewriting × 复制成功/失败，来源不变、整理不取消、完成后无自动派发；前端真实组件 handler 用受控未完成 Promise 验证重试期间复制仍可用。

## 容量和质量边界

自动整理的单次来源预算为 **完整 sourceText 经 JSON 编码后 6144 UTF-8 字节**，相对 8192-token 输出 envelope 保留编辑/格式余量。它是保守工程边界，**不是精确 tokenizer 或真实模型质量保证**；纯中文通常约两千字，英文和转义字符的实际容量不同。来源原有的本地存储/复制容量不变。

本轮未实现任意长稿自动分块。超限返回 `rewrite_source_too_long`、stage `rewrite_capacity`，直接保留来源，不反复消耗云请求。统一 reviewer 也不保证所有事实错误一定被真实模型识别；脚本化 reviewer 测试验证的是路由、来源绑定、拒绝与修复次数。

## Code review 后续修复

用户指定修复前三项，第四项“换用单次时长更短的 ASR 服务前提前拒绝超限缓存”保留，不在本轮实现。

1. **纠正阶段保留永久错误分类**：`CloudError::forbids_automatic_rewrite_retry()` 统一不可立即自动重试的策略，供 engine、纠正及错误适配共用。纠正生成/最终复核中的 401/403、429、其他 4xx、refusal、配置/凭据/容量及 stale 错误不再被原内容拒绝覆盖；取消/超时仍保留优先级。真实生产管线的 loopback 回归覆盖两个阶段 × 六种响应，并在 AppHub 层验证没有第二轮、没有 Ready/usage/输入，来源保持原样。独立 HTTP 探针也验证 401/429/400 均不再满足自动兜底条件。
2. **复制只接管交付**：增加独立、仅适用于原始有效上下文的复制接管许可。冻结逻辑及在途目标/上下文回执统一检查此许可，复制发生在冻结前或后时保留一致的场景、宿主上下文及场景画像。版本操作、重试、取消、失败、上下文清理和到限会撤销旧上下文，重复复制不能重新授权。回归包含邮件/聊天/浏览器场景、实际保存的场景画像、在途目标/上下文读取及失效场景。
3. **最终采音收尾确认时长上限**：将到限策略统一到 `apply_recording_cutoff()`。排空全部原生尾帧后、发送 Finish 之前，根据最终原始样本数或实际帧预算确认是否到限，独立于手动 stop 和进度更新时间。到限一律 Preview，撤销输入许可、目标与上下文；保留手动停止时间。回归覆盖手动 Stop、滞后 heartbeat、超限尾部、未到限的完整尾帧、取消和旧会话回执；最终仍正常保存来源/成稿，不能自动输入裁剪后的文字。
