# Mode 整理方案选择实验：预注册

日期：2026-10-09。生产基线 `55a5b3b` / `mode-contract-v1`。本文件在任何新云端调用前建立；不改写此前两轮失败记录。

## 目标与实验臂

用户授权进行真实实验并选择效果最好的方案。比较范围是文本整理，不包含麦克风、ASR、跨应用输入或真人任务耗时。

| arm | 模型 | 处理方式 |
| --- | --- | --- |
| baseline-flash | qwen-flash | 当前生产 prompt、协议与检查 |
| fewshot-flash | qwen-flash | 精简任务合同与独立对照样例；原协议与检查 |
| typed-flash | qwen-flash | 编辑单元、组织计划、代码渲染；最后进入现有检查 |
| typed-plus | qwen-plus | 与 typed-flash 相同的候选协议与代码，只改变模型 |

均使用已有账号地域、JSON Object、非思考、temperature 0.2、max_tokens 8192、单次 20 秒上限。实验不会写 provider_config 或修改生产默认。typed 路线是实验适配器，来源暂折叠为一个覆盖全部输入的父块；通过实验也不意味着已完成生产逐句恢复的数据迁移。

## 数据与隔离

由独立 Agent 编写 20 条新的合成语料：8 条筛选、12 条确认，均执行 light/structure/auto。明确标注 AI 编写，非人类采集、真实录音或真实用户研究。候选作者不读取新语料；语料作者不读取候选实现；来源、评分说明、候选文件和请求体在执行前保留 SHA-256。确认集不得用于提示词修订。

- 筛选：8 × 3 × 4 × 1 = 96 次。
- 确认：12 × 3 ×（基线＋筛选胜出候选）× 2 次重复 = 144 次。
- 总上限 240 次；不自动重试，不在见到结果后增加实验臂、调整提示词或更换语料。授权失败的模型停止，限流或累计三次服务/网络失败停止；跳过、拒绝和失败保留在计划分母。
- 各输入/模式/重复交错轮换 arm 顺序；顺序请求避免并发干扰。保留每次延迟与 token 使用，不把单次快慢外推为端到端速度提升。

## 评分与选择（输出前固定）

对结果隐藏 arm/model 后按语料要求做内容复核；由 Agent 复核，并非真人盲评。可合并完全相同的同案例同模式输出以减少重复复核，但映射回每次调用计数。关键词机器检查只提供诊断，不替代意义判断。

每次调用记录：

1. 协议接受：解析、映射、本地保护检查是否通过；拒绝算不可交付。
2. 语义完整：必需事实、观察行为、判断归属、条件、否定、数量、疑问是否保留；是否新增事实。明确遗漏/改变为失败，不能靠文风抵消。明确矛盾、数值/否定/条件变化另标为关键错误。
3. Mode 任务：Light 保序和清理，Structure 有用分组且不强行提炼，Auto 在允许集合且正文匹配任务。清晰短句允许不同 Mode 相同。
4. 可交付任务通过：以上全部通过。边界争议保留具体理由并按保守失败计，不删案例。
5. 性能：实际请求 p50/p95、每成功交付请求数、输入/输出 token；不假装完成插入延迟测试。

筛选候选依次按可交付任务通过数（高优先）、关键语义错误数（低优先）、全部语义通过数（高优先）、p95 延迟（低优先）选出一名，和基线进入确认。候选全部弱于基线仍如实选出相对最好者做确认；若全部未获模型权限则不执行无意义的确认。

最终“本次效果最好”按确认结果相同顺序比较。若候选总通过更多但关键错误比基线多，不推荐替换默认；若总通过相同，优先关键错误少者，再比较语义通过；仍相同则保留基线，避免以小样本延迟差作为质量升级证据。

自动替换生产默认另需：确认可交付通过率至少 95%、无关键错误、相对基线任务通过至少提升 10 个百分点、每一 Mode 不退化，并完成来源恢复兼容和生产回归。未达到时仍给出实验优胜方案和具体不足，不将其冒充可直接发布版本。
