# 长口述差距定位与流程实验

日期：2026-10-12。状态：**候选研究，未推广或发布**。应用版本仍为 0.2.16，现有运行程序未停止、替换或安装。方案见[长口述计划](../plans/long-cleanup-0.2.17.md)，元数据见[实验收据摘要](long-cleanup-0.2.17-2026-10-12-summary.json)。

## 最主要的发现

用户看到的长段输出是整理失败后交付的原始识别文本，而不是模型通过检查后的成稿。只加去语气词提示不能解决这种实际交付路径问题。同时，生成模型确实会省略细节、混淆流程层级或猜错专业术语，不能把全部失败归咎于规则太严格。

只读核对确认运行 EXE 为已交付的 0.2.16，哈希与发布收据相同。匹配历史的录音为 326.720 秒，24 个最终 ASR 片段完整保存，共 1503 字符（包含分片换行）；最终文本与完整 source.text() 逐字相同。停止到产出为 10.376 秒，rewriteFallback 为 meaningRisk，非超时。历史没有保存被拒绝草稿或具体检查阶段，因此本轮复现能说明当前机制，不能冒充原会话内部响应。

同一会话另有 targetChangedBeforeDelivery 导致输入跳过的记录。它是独立的原生交付问题，本轮没有复现目标窗口，也未弱化焦点检查。

## 规则错误与源码修复

冻结旧协议响应的离线检查发现两个误判：

- “每一次请求”与“每次请求”被当作次数事实消失。现在统一为逐次频率事实，仍拒绝删除频率、改成一次或两次。
- “有没有被替换”里的“没有”被当作否定陈述，因而拒绝“是否被替换”。现在区分极性疑问；“是否没有被替换”中的真实否定仍保留，更长的能力疑问仍优先识别。

同两份冻结响应的前置检查现在通过，但它们仍有实质文本问题，**前置检查通过不是语义接受或实际交付**。没有关闭数值、否定或语义核对。

还增加了固定诊断码 rewrite_admission_rejected 与 rewrite_semantic_rejected，使今后能区分前置检查和模型核对拒绝。两者仍走既有 MeaningRisk 回退，取消与来源无效不会成为可交付回退。常规诊断不包含原文、术语映射、数值键或核对引文。

## 23 次云端文字实验

全部使用冻结的完整来源，未采集新音频、修改个人模型/词典或触发原生输入。生成不重试、不重新挑稿。请求与原始响应保存在仓库外私有验证目录。

原基线第一臂使用上轮已编译的实验程序（标记 0.2.15），其 fluent-v1/compact-review-v2 请求协议与 0.2.16 一致；后续使用当前源码重编译的工具。该区别保留在收据中，没有把旧程序标成新版本。

“独立评审”是另一代理只看 source/draft 的全文判断，不是人类标注或语义证明；臂文件名可见，因此不声称完全随机盲评。六例在候选前冻结，现已曝光；后续修改必须使用新的独立测试，不能重复宣称这些是未见预留集。

## 有增益的工程路径

候选流程为：**本地隔离源文专名 → 全文接句与组织 → 本地验证并恢复词形 → 事实前置检查 → 完整来源与成稿复核**。

短标记单例的“嗯/呃/啊”字符从 43 个降到 0，1503 字符整理为 1093 字符。字符计数只描述这条材料，不是普遍语气词识别率。保住了预算、接收方备选、SVID 与 SPIFFE ID 的区别、三阶段和两个子流程，也没有再猜出不存在的框架全称。

代价是约 14.6 秒的固定文本等待，且原始错词仍被保留。保护只保证不同原文词形没有合并或新增，不能证明动作归属、数量、中文事实与引用含义正确。长标记明显增加复制成本，短标记通过碰撞检查在本请求内隔离文本；它不是认证凭据或跨会话身份。原始 source 与 mode 的完整哈希绑定仍保留。

这条候选只在实验 API 中可选。普通 dispatcher、用户配置与安装版没有切换。最后三个完整生成预留正例在关键核对失败后未运行，不计通过。

## 专有词差距来自哪里

本次历史 source 使用 qwen3-asr-flash-realtime。现有适配器会尝试发送 corpus.text，但源码明确将其标为 LegacyCorpusUnverified；官方旧客户端参数表没有列出该字段。正式即时热词能力文档列有 Qwen Audio 3.0/3.1 等，不能把旧接口的发送成功等同服务端采用热词。[旧客户端协议](https://help.aliyun.com/zh/model-studio/qwen-asr-realtime-client-events)、[识别准确率增强](https://help.aliyun.com/zh/model-studio/improve-asr-accuracy)

当前词库有限查询已有多个相关专名，但整理提示只选大写开头、源文精确匹配的英文词条；小写词条、字母被空格分开的缩写、同音识别错误常常不进入提示。这并不是具备纠错能力的词典检索。历史又没有保存当次词库版本，不能根据当前词库断言某个词当时已被服务采用。

下一步优先比较正式支持热词的识别路径，使用同一音频测量术语错误与耗时；再增加明确词典别名、逐字引语/代码保护和新的独立长文挑战。不要让格式整理承担无证据的专业词猜测，也不要把 Typeless 的输出直接当真值——它的缩写展开、组件角色和结论强度同样需要核对。

## 验证与交付边界

最终 Rust library 704 passed / 0 failed / 3 ignored；admission probe 2 项、实验 runner 6 项、Python 诊断导出 33 项通过。覆盖了频率/问句/真实否定、阶段错误码、取消与一次交付、专名完整性和碰撞、来源不变及隐私字段过滤。未修改 UI，因此没有重跑无关的浏览器排版测试。

本轮已在源码修复规则及诊断，并保存候选实现、失败记录、独立评审和计划；未构建新安装包、未启动或停止应用、未推送 Git。当前安装版的体验不会因这些源码修改自动变化。文本实验不能代替录音质量、粘贴位置或安装升级验收。
