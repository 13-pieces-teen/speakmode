# 统一快捷键开始/结束与误触取消：0.2.43

## 用户交互规则

对设置中的任何有效录音快捷键采用相同规则，F8 只是其中一个例子。

| 当前状态与触发 | 结果 |
| --- | --- |
| 空闲，第一次完整触发快捷键 | 开始本条录音 |
| Starting / Recording，第二次距首次触发不超过 500ms | 视为误触，取消本条并收起浮层，不进入最终识别/整理/输入链路 |
| Starting / Recording，第二次距首次触发超过 500ms | 截止采音，继续正常最终识别、整理和结果处理 |
| 正在处理或释放实际资源 | 不开启新采音，也不把已结束的本条再次停止或取消 |
| 取消/结束完成前已排队的旧触发、旧系统生命周期的触发 | 忽略，避免稍后自行重开录音 |

500ms 是本次采用的统一默认阈值，包含恰好 500ms；不是仅针对 F8 的特殊规则。按键识别仍要求一次有效的完整手势，重复 key-down、组合键误用与 injected 事件不会变成多次有效触发。主面板结束按钮继续直接结束并整理，不使用快速连按阈值。

首次触发已经开始的实时识别可能存在在途工作；误触取消撤销它，禁止本条进入最终整理和自动输入，不声称首次触发后从未发起过实时识别。

## 原逻辑缺口与修改

原来的快捷键处理直接按当前 phase 切换，缺少第二次触发间隔的语义；桌面又为每次 Toggle 单独 spawn 异步任务，不能依靠这个入口保证快速触发的处理顺序。

- 原生观察事件记录 hook 入口的单调时钟，完整手势携带原释放时间，避免监听线程、菜单屏蔽或异步队列延迟改变短间隔判断。
- 桌面使用容量 32 的 FIFO 和单一消费者处理 Toggle，保留原触发时间及 lifecycle epoch。队列满或关闭明确报错；锁屏/中断仍立即撤销准入，不排在 Toggle 后面等待。
- 会话保存原开始意图时间，由共享 action 判定选择 Start / Stop / Cancel / Busy / Ignore。所有快捷键进入同一个判定，不读取 F8 特例。
- 快速取消走既有内容清理、原生监听恢复及实际 worker 释放约束；收起浮层使用会话 ID/generation 二次确认，迟到取消不会隐藏新浮层。
- 记录终态及控制操作完成的时间边界，取消、慢停止完成后不消费旧排队输入为新的 Start；旧会话回执不能更新新会话边界。

## 代码验证边界

新增覆盖 F8、F9、Ctrl+K、右 Alt、右 Shift 的完整手势计数与统一时序策略；0、499、500、501ms 的阈值边界；启动中与录音中快速取消；普通第二次停止；模拟慢启动后的 FIFO 和原时间保持；系统生命周期失效；取消后及慢停止后的旧输入；迟到浮层收起；处理中不重复切换。
