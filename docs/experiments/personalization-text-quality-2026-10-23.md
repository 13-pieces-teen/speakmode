# 个性化文本整理对照 · 2026-10-23

状态：4 条开发文本与 60 条独立文本已完成实测；暴露的问题进入修复，真人录音与用户采纳尚未运行。本报告不作为全量发布或默认启用的依据。

## 问题与方法

检验职业介绍是否提供额外帮助，以及明确表达习惯是否改变成稿。四组使用相同原文、场合、语言、空词典、模型配置和整理链路：A 基础整理；B 仅职业背景；C 完整画像；D 保留 C 的任务、对象和习惯，删除 profession、domain、description。

先冻结 C，再通过删除字段派生 B、D，避免预算变化导致其他字段被补进请求。身份名称、ID、版本及来源不进入供应商数据。无有效内容的消融归为 None；没有适用职业字段的样例不纳入职业对比。D 的原文、常见任务和沟通对象仍可能提供领域线索，因此 C/D 仅衡量额外显式职业介绍的增量。

职业/习惯内容通过当前生产生成、复核及一次可选局部修复路径传递。实验使用专用无重试、无跳转客户端，每例四组最多 16 次请求，每组共用 20 秒总期限；每次请求前同步保存账本，写账失败则停止。计数是客户端授权的管线请求开始次数，转换或取消可能发生在 HTTP 发出前，不代表供应商账单。鉴权、限流及超时会停止后续组。

固定配置：Aliyun / `qwen3.8-flash`，本机原生凭据；只读 provider_config，不打开应用 Store、不迁移用户库，不读取用户画像、词典、历史或录音。词典为 `FIXED_EMPTY_DICTIONARY_SNAPSHOT`。原文与画像均为匿名合成文本。

预检计划与执行必须精确匹配数据、配置、代码和二进制哈希。长中文分支的随机守卫前缀仅在预检哈希时归一化，实际生产请求不修改；该哈希不能称为 HTTP 原始请求哈希。

在职业对比适用且 C/D 均通过的 45 对中，31 对成稿完全相同。其他 14 对的差异不自动代表职业背景有益；没有用户盲选、编辑负担或独立多次运行支持“职业质量提升”。上述单次、固定 A/B/C/D 顺序也没有控制服务波动或顺序效应。

## 复现

在项目规定的 Windows MSVC 环境构建 example 后，运行以下入口（所有路径均为绝对路径）：

```text
personalization_quality_lab.exe CONFIG_DB FIXTURE NEW_OUT EXACT_CASE_ID --plan
personalization_quality_lab.exe CONFIG_DB FIXTURE NEW_OUT EXACT_CASE_ID --run
```

每次只接受一个精确 case ID；输出及账本必须不存在，计划文件仅可创建一次。`--plan` 不读取凭据、不联网；`--run` 复用相同 NEW_OUT 并校验冻结计划。原始回执、逐请求账本、盲审材料及日志保存在工作区 `output/`，不进入产品诊断或 Git。
