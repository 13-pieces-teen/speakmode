# SpeakMode 0.2.1 实施与验证

日期：2026-10-09。基线为 0.2.0 合并提交 `de2b6d0`，桌面 0.2.1／前端 0.4.1 已完成本地验证和独立构建，实际使用验收待完成。[版本计划](../plans/voice-0.2.1.md)定义本轮范围。本机日志与截图位于 `D:/Codex_Project/SpeakMode_Dev/evidence/voice-0.2.1-2026-10-09-r1`。

## 相比上一版的变化

1. 失败音频保留原 30 分钟期限，到期主动清理；不再只关闭重试按钮而继续持有 PCM。
2. 开始下一条时，可将上一条完整、可重试的 ASR 失败放入一条内存恢复槽。主面板显示「打开恢复」及需确认的放弃操作。打开本身不调用云服务；再点击「重试识别」才请求识别，结果不自动补发。
3. 两条均为 ASR 失败时允许明确交换；槽已满时开始第三条会提示先处理已有条目，不静默覆盖。未保存内容也不被新录音覆盖。原始期限、来源保护、资源释放与 generation 检查保留。
4. 词典显示保存数据的实际编码容量；新增、编辑和批量草稿显示合并前上限，提醒可能超限。服务端 Unicode 去重仍是权威，提示不禁止提交；失败保留整份草稿。
5. 主面板在自动输入 Prepared／Dispatched 阶段不显示「查看成稿」，与录音浮层遵循同一状态契约。

## 已执行的前端验证

- 9 个 helper／组件脚本全部通过，总计 76 项；其中词典 helper16、词典容量组件5。
- 恢复入口生产 React + 合成 Tauri bridge：14/14，通过原身份 payload、显式重试、交换后确认意图重置、到期通知、旧身份高版本快照恢复、迟到事件拒绝、资源未释放／未保存保护、两种发送中状态等场景。
- 词典容量浏览器：5/5，通过新增、编辑扣除旧词、批量／去重、超限保留草稿、冲突重读版本等场景。
- 既有来源恢复／交付11、纠词／个人表达6、模型设置6项浏览器回归通过。
- 界面在 430、720、800 的相关场景无横向溢出；截图已检查。原生桌面最小宽度仍为720；430是浏览器布局回归，不代表原生窗口验收。
- 各套浏览器记录均无页面错误或外部请求；使用合成数据，不操作个人资料、真实剪贴板或输入宿主。

基线恢复 UI 的10个预登记场景全部失败：8个缺少恢复卡，2个在发送中错误显示查看按钮。修复后结果另存，不覆盖基线失败。只读复核另发现「无内容的凭据预检失败」被误判为未保存内容，已有失败音频因此无法从界面打开；单项浏览器 RED 后收窄为按实际可恢复内容判断，最终14项通过。中途 TypeScript 检查曾暴露词典草稿联合类型未收窄，修复后检查／构建通过。

## 原生回归与交付

原生13项恢复生命周期回归通过，分别覆盖到期真实释放、关闭界面后的定时清理、开始新录音保留旧条目、显式激活、容量与双向交换、资源准入、未保存冲突、精确放弃／幂等、到期取消worker、迟到回执、通知竞态及锁屏／退出。

复核增加 Ready／AlreadyCompleted 的锁屏清理回归，先观察缓存未释放的失败，再在中断边界仅清音频；保留成稿、来源和Ready状态。普通成功路径原本已释放PCM，本修复补的是提前完成等防御边界。

另一条取消边界同样先验证失败：数据库清理失败将状态置为 Failed 后，迟到的采音结束仍会回填音频。实际采音缓存接收路径现同时检查取消令牌；即使状态不是 Cancelled，也不能重新持有已取消音频。回归保留清理失败状态，不伪造数据库处理成功。

## 保持开放的边界

本轮没有云端调用、真实麦克风或物理右 Alt 输入实验，也没有更换默认模型。它改善失败恢复、容量反馈和操作时机，不证明识别准确率或模型质量提高；0.2.0的 Flash 复杂改口限制仍适用。

到期释放指进程不再持有恢复音频，不能声称系统内存已安全擦除。恢复槽不跨进程重启持久化，也不充当完整历史记录。现有复制后因目标变化导致剪贴板改变的问题仍属于 O10，未增加富文本／图片格式回滚。

真人／实际宿主输入，以及安装升级卸载继续待独立验收；测试数量和浏览器合成 bridge 不代替这些结果。
