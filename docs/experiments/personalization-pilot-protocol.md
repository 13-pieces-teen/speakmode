# 个性化真实任务试用协议

状态：用户已有“都还可以”的初步定性反馈，并报告多个应用自动输入失败而手动 Ctrl+V 可用；尚无逐任务原文、成稿、人工目标稿及采用记录。不得将这些反馈填成六项任务均已完成或质量合格。对应个性化 PRD 的试点验收，不替代独立文本评估。

## 参与及设置

建议 5 名自愿试用者，每人完成 6 个任务，按人和场合分别报告。人数和任务数只是试点规模，不支持总体人群显著提升结论。身份与偏好由试用者自己填写，可跳过职业介绍。记录匿名参与者编号、画像版本、场合、输出语言、供应商/模型及基础配置；原始正文、音频与凭据均不提交仓库。

先确认麦克风、实际快捷键与目标输入正常。试用采用候选版本，普通录音等待和交付行为保持真实配置；不得为了让试用成功而使用文本实验的 20 秒扩展期限。

## 六个任务

| 编号 | 任务 | 需要观察 |
| --- | --- | --- |
| T1 | 给同事的一段工作进度，包含已完成、待验证和下一步条件 | 状态及归属是否保留，段落是否符合本人习惯 |
| T2 | 给客户的一段说明，包含材料前提、时间范围和不确定性 | 是否补出承诺、漏掉条件，正式程度是否合适 |
| T3 | 给朋友的一段普通聊天，仍使用工作画像 | 职业是否越界，语气是否自然，否定和数量是否保留 |
| T4 | 至少 45 秒的中英混说，包含真实使用的术语 | 分开标记 ASR 原始错误与整理新增错误，是否保留有效中文 |
| T5 | 一段明确列举，并含一个字母/标识符/逐字字符串 | 列表是否适合，必要空格及拼写是否保留 |
| T6 | 一段有即时改口的表达，录制后再调整一个明确表达习惯 | 改口是否作用于正确对象，相同原文的对照是否满足新习惯 |

口述内容由试用者自然表达，避免要求背诵唯一标准答案。口述结束先确认原始识别表达的意思，再比较同一份识别原文的基础稿和个性化稿。两稿匿名展示并交替左右顺序，记录来源映射但不提前告诉试用者；不能通过两次不同录音来冒充相同输入对照。

## 记录方式

每个任务先记录真实录音的停录至可用耗时、交付/原文回退/失败/取消，以及目标应用是否成功接收；再进行固定原文的对照。对照延迟单独记录，不能混入录音延迟。

两稿分别记录：

- 事实问题：遗漏、错误增加、条件/否定/对象改变，及其严重性。
- 表达习惯：本次哪些偏好适用，哪些实际执行，哪些不适用。
- 直接采用：无需改内容 / 仅改排版 / 需要改内容 / 无法采用。
- 修改负担：开始编辑至愿意使用的实际秒数，最终文本，新增/删除/替换字符数；由记录计算，不能从生成耗时推断。
- 本人比较：更喜欢基础稿 / 无明显差异 / 更喜欢个性化稿，以及一条具体原因。

同一稿被连续编辑会产生熟悉效应；交替先编辑的版本，保留顺序。参与者看到前一稿后受影响的情况要记录，不能当作严格双盲实验。

建议本地 CSV 字段：

```csv
participant_id,task_id,scene,profile_version,provider,model,recording_outcome,stop_to_ready_ms,host_received,comparison_outcome,left_arm,first_edited_arm,base_adoption,personal_adoption,base_edit_ms,personal_edit_ms,base_edit_chars,personal_edit_chars,base_fact_issues,personal_fact_issues,applicable_preferences,executed_preferences,preference_vote,reason,evidence_path
```

缺失值写 UNKNOWN，未执行写 NOT_RUN。CSV 及证据保存在试点专用本地目录，路径可指向个人可控文件；禁止填凭据。不自动修改任何人的系统画像或打开录音。

## 报告与决策

分母分别列出招募者、实际参与者、尝试任务、有效成对对照、回退/失败/取消和明确投票。职业增量使用额外固定文本消融，不能将全部画像与基础稿的差异都归给职业。

先检查新增事实错误及跨场合误用，再看直接采用和修改负担。若短句更直接、段落更规整但本人不喜欢，记录为偏好不合适，不强行给高分。若两个稿相同，记录无差异。小样本只支持下一步迭代，不制作“个性化提升百分比”图。

## v2 本地计算入口（2026-10-25）

`scripts/personalization-pilot-report.py` 读取明确给定的 CSV 和正文文件，计算 Unicode 字符最小编辑距离、偏好执行分子／分母及盲选票数；不读应用数据库、不联网、不调用模型，报告不包含正文。原文回退也使用用户实际拿到的文本计算修改量，不排除输入失败。界面显示“按键已派发”时，目标接收仍是 UNKNOWN，不能填 `host_received=yes`。

沿用上述 CSV 的参与者／任务、场合、配置、录音结果、交付和评判字段，并使用脚本 `FIELDS` 中的完整列名。新增或明确以下字段：

| 字段 | 填写规则 |
| --- | --- |
| `recording_outcome`、`base_outcome`、`personal_outcome` | `passed` / `sourceFallback` / `failed` / `cancelled` / `UNKNOWN` / `NOT_RUN` |
| `host_received` | 使用者实际确认后的 `yes` / `no`；仅派发回执为 `UNKNOWN` |
| `base_text_path`、`personal_text_path` | 用户实际拿到的两份文本；回退时填回退原文文件 |
| `base_final_path`、`personal_final_path` | 本人分别修改并确认愿意使用的正文；未编辑或未确认时填 UNKNOWN，不把空字符串当零修改 |
| `personal_added_serious_errors`、`personal_scope_violations` | 逐项核验后的非负数量；不清楚填 UNKNOWN |
| `preference_vote`、`blind_order_recorded` | `base` / `tie` / `personal`，及是否确实记录匿名展示顺序；无顺序证据的偏好保留但不计盲选 |

路径可相对 CSV 所在目录，或明确指定绝对路径。输入正文和 CSV 保存在仓库外的试点目录。脚本拒绝重复参与者／任务、负数、执行条目多于适用条目，以及覆盖已有报告。未执行不进入尝试数，缺少人工目标稿不计零修改，零基线修改量不计算提升百分比。部分已知严重错误会标记 FAIL，即使其他判断仍缺失；所有质量和发布门槛始终分别列出。

```text
python scripts/personalization-pilot-report.py --csv ABSOLUTE_PILOT_CSV --out ABSOLUTE_FRESH_REPORT_JSON
```

该报告仅核算真人试点记录，不能单独接受完整 PRD。四组冻结模型质量、职业增量、可靠性及在线延迟仍需各自证据。
