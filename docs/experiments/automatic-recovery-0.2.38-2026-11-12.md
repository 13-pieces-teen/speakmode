# 0.2.38：整理失败优先进行兜底自动整理

用户反馈：长口述有时只得到“基础整理”，希望异常默认进入自动整理兜底。

## 行为

此前初次整理遇到可恢复的超时、网络、无效响应或原意检查失败时，直接采用受审草稿或本地基础整理。现在先用同一份完整、已冻结的识别稿执行一次独立自动整理。兜底仍包含生成、原意复核，以及现有的有限修正流程；一次兜底不等于一次 HTTP 请求，不进行无限重试。

兜底使用普通自动模式，保留开始录音时冻结的词典和输出语言，移除自定义规则、应用场合、输入位置上下文和个性化画像。主流程和兜底共用原本的供应商、模型与凭据。兜底按完整正文的 Unicode 字符数单独计时：不超过 800 字为 20 秒，801–3000 字为 30 秒，超过 3000 字为 60 秒。主流程时限不变；异常路径可能等待更久。

兜底成功后标记为 `automaticRewrite`，显示“已完成兜底自动整理”或“自动 · 兜底”。原先选择的模式快照保持冻结；恢复元数据说明实际采用自动整理，因此允许最终排版与原模式不同。历史、编辑与撤销仍使用原有版本机制。

兜底再次失败时，优先采用兼容原模式且通过完整含义检查的受审草稿，最后才执行本地基础整理。缺少可用服务、持续网络故障或无法通过原意检查时，不能保证云端自动整理完成。原始识别稿始终独立保存。

整个恢复过程中没有提前保存或投递基础版本。最终仅保存、统计与投递一次。取消或替换会话、不完整或无效来源、待保存冲突、已撤销投递权限不获得新的自动投递资格。显式历史整理与手动重试继续使用原有交互。

## 诊断与验证

诊断保留主流程失败原因，并新增 `automaticRecovery` 的预算、复核是否通过和固定错误码。重复阶段的请求按开始时间区分；请求记录容量限制为 12，不记录正文、响应或密钥。

- Rust 完整库回归：1102 passed，0 failed，4 ignored。
- 新增回归覆盖长文主流程超时、网络异常、无效响应、复核拒绝后的真实本地 HTTP 生成与复核，以及兜底拒绝、独立时限、取消、会话替换、输出语言与模式快照/历史/撤销约束。
- TypeScript 检查及输入反馈辅助检查通过；辅助检查包含新的 `automaticRewrite` 显示。

这些是合成来源、本地 HTTP 与 SQLite 验证，不代表真实麦克风、云端服务或目标应用输入已验收。当前用户的真实长语音仍需在安装新版后验收。

验证日志位于未纳入版本控制的 `.validation/automatic-recovery-*.log`。
