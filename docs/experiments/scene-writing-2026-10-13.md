# 场景感知自然成稿：实验与升级评估

日期：2026-10-13。源码基线 `a6858f3` / 桌面 0.2.20，模型为北京 `qwen3.8-flash`。

**本轮选择“稳定语义整理＋本地场景呈现”作为下一步产品集成方向。** 云端场景方案在预留集上改善了聊天格式，但完整可用文本仍为 7/8，与现有方案持平；一次超时抵消了格式收益。随后用 6 条新素材验证本地呈现，完整可用文本从 4/6 增至 6/6，增加云端请求为 0。

这是合成文本实验和实施 Agent 的逐条评阅，结论适用于选择下一步实现方向。真实录音、实际应用上下文、人工修改时间和原生输入均未验收。候选尚未接入日常听写或替换默认模型/流程。

## 比较对象与评分口径

[实验登记](../plans/scene-writing-evaluation-2026-10-13.md)先于各轮运行保存。第一组为 8 条开发素材和 8 条冻结预留素材，每条三臂；开发诊断完成后冻结 v2，再执行全部预留比较。第二组为后续单独登记的 6 条新确认素材。合计 22 条不同素材。

| 臂 | 实际流程 | 比较含义 |
| --- | --- | --- |
| baseline | 当前 minimum-edit-v3：生成、复核，必要时最多一次局部修复 | 日常整理的当前基线 |
| natural | 新的自然成稿生成/复核协议，通用场景，无附近文本 | 整套整理策略替换的效果 |
| scene | 与 natural 同一协议，加入冻结的场景和可选合成附近文本 | 同一策略下场景信息的效果 |
| layout | 同一次 baseline 已通过核对的结果，再做本地场景呈现 | 不增加模型请求的格式收益，仅在新确认集运行 |

模型、来源、Mode 和长度对应的 5/8/20 秒期限保持一致，三臂按案例轮换执行顺序。所有正常失败、回退均留在分母。baseline→natural 同时改变了生成提示、复核提示和修复策略，不能把全部差异归因于提示长度；natural→scene 才用于隔离场景输入。所有案例使用空词典。

**完整可用文本**要求四项同时通过：意思/事实/限定/意图保留、表达可读、场景合适、Mode 合适。它尚不包含 ASR 和宿主输入成功率。模型放行率单独记录，不能充当质量评分。

评阅包隐藏臂标签，但实施 Agent 知道实验设计，不能称独立或真人盲评。每条记录具体理由和最少必要修改参考；“建议修改字符”按 Unicode 编辑距离计算，是审阅判断，非真人操作时长。每个案例只运行一次，样本小且受服务/网络时段影响，不报告显著性或 P95。

H01 的现有结果强制给普通聊天加编号，scene 改成自然表达；H05 的 scene 在 5 秒期限内未完成，返回含口头语的完整原稿。两项一增一减，完整可用数持平。H07 保留聊天中的显式结构 Mode，H08 未采用附近文本中的虚假发布状态。

“最终文本忠实”包含失败后保留的原稿，不表示全部模型候选均正确。本组未观察到放行后事实误改，仍不足以证明一般场景的准确率或抵抗上下文污染的能力。决定：**云端 scene v2 保留为实验候选，本轮不升级为默认链路。**

## 新确认集：本地呈现保留了聊天收益

三臂结果出来后，另行登记了本地呈现假设并冻结 6 条新素材。每条只调用现行整理一次，两种文本使用同一份结果；本地候选没有第二次生成或语义复核。此组用于确认新的工程路径，不能并入原预留成绩。

| 指标（每臂 6 条） | 同一次 baseline | baseline＋layout |
| --- | ---: | ---: |
| 完整可用文本 | 4/6 | 6/6 |
| 最终文本忠实 | 6/6 | 6/6 |
| 场景格式合适 | 4/6 | 6/6 |
| 建议修改字符合计 | 12 | 0 |
| 云端请求 | 12 | 额外 0 |
| 完整流程耗时中位数 | 2,335 ms | 2,335 ms（毫秒取整） |

本地判断耗时 75–128 微秒；实际转换的 C02/C03 分别为 128/117 微秒。C01 已经自然成段，C04 为文档，C05 是显式结构 Mode，C06 口述明确要求清单，这四条均保留现有结果。

C02 的实际对比如下，数字、条件、否定和每个句子字符均未改变：

```text
baseline:
1. 帮我先检查蓝牙麦克风，再确认一下系统权限，最后录一段十秒的音频。
2. 如果蓝牙断了就停下来，不要自动换成外放。

layout:
帮我先检查蓝牙麦克风，再确认一下系统权限，最后录一段十秒的音频。
如果蓝牙断了就停下来，不要自动换成外放。
```

该原型仅处理 Auto、无个人规则、聊天场景中不超过 400 字的 2–6 条完整平级列表，移除经过检查的列表前缀。显式要求清单/编号、引语、代码、嵌套或不完整列表均保持原样。C06 的评分按登记中的清单意图执行，不据此宣称支持通用口述指令。

它验证的是语义整理与场景呈现可分开承担职责。完整产品仍需要应用/任务偏好、上下文采集、目标一致性、用户控制，以及更自然的接句、改口和段落组织。

## 实现与验证

- [场景候选](../../app/src-tauri/src/cloud/rewrite_scene.rs)：来源/Mode/场景哈希绑定、会话代次检查、显式 Mode 优先、可选附近文本上限 1024 字符。附近文本停用时，生成和复核均不发送。复用确定性来源检查、严格五项语义复核、共享绝对期限和取消优先。
- [本地呈现原型](../../app/src-tauri/src/cloud/rewrite_scene_layout.rs)：仅产生带来源及输入/输出哈希的候选，不产生输入授权；实验工具只在 baseline 已放行时使用。
- [有限实验工具](../../app/src-tauri/examples/scene_writing_lab.rs)：只读配置及正常凭据入口，固定模型/地区，每轮限制请求数，401/403/429 停止，并保留逐条写入的 JSONL。不读取个人历史、音频或真实应用正文。
- [离线评阅工具](../../scripts/scene-writing-review.py)：检查冻结来源、Mode/上下文、样本完整性、请求账本、完整原稿回退和显式评分，不把模型放行转为语义正确。

最终 Rust 全量测试 **760 通过、0 失败、3 忽略**；离线评阅工具 **7 通过**；实验程序编译成功。新增测试覆盖场景/目标/来源变更、停用上下文、超限、取消/期限、错误事实的拒绝，以及本地排版保留显式要求、数字、否定、代码和来源引用。构建缓存 11.271 GiB，未超过本工作区 12 GiB 上限。

## 下一步产品集成与验收

1. **让 Auto 真正知道写作任务。** 实现本地应用/控件能力和用户表达偏好；浏览器中任务不明确时使用通用场景。停止时冻结目标和场景；录音中切换应用后，旧场景不得影响新目标。
2. **形成完整的场景成稿路径。** 当前通过核对的语义结果进入场景呈现层，保留来源对照、恢复和显式 Mode。扩大聊天、文档、技术说明的同源语料；把接句、局部语病、改口和段落组织列为独立质量项，继续解决 D08 类表达问题。
3. **按增益引入附近文本。** 先实现明确开关、范围和应用排除，再比较术语/接续收益。通过 REA 继续查 `collectFullContext`、`replace_audio_context`、`ContextHelper.dll` 的字段、时机、焦点变化和失败处理；服务端成稿质量继续靠自己的实验判断。
4. **以实际任务验收升级。** 冻结新的独立素材，并补真人录音与宿主应用检查，记录一次口述直接可用率、实际修改、停止到文字出现的时间。出现事实污染、目标变化后误输入、取消后输入，或总体可用率未超过“现有整理＋场景呈现”基线时，继续保留实验状态。

本轮交付覆盖实验实现、真实模型运行和升级决策；上述产品集成仍待实现。阶段路线见[体验升级计划](../plans/typeless-inspired-product-upgrade-2026-10-13.md)。
