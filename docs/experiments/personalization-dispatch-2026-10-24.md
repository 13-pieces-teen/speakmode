# 个性化请求统计 · 2026-10-24

本轮将“本次选中了画像”与“客户端发起了含画像参考的 HTTP 请求”分开。此变更修复使用数量的证据口径，不改变生成、独立复核、局部修复或放行合同，不证明模型采用画像、供应商收件、计费或成稿质量提高。

## 发送边界与去重

原 timing observer 在供应商请求转换之前启动，保留用于期限、阶段耗时及实验调用预算。新增独立的内容无关 dispatch observer，发生于供应商转换、URL／请求头／序列化构建成功和取消／期限检查之后，进入 `client.execute()` 之前。事件仅含阶段与转换后用户 JSON 是否有顶层 `personalization` 对象的布尔值，不含文本、规则、职业、身份或凭据。没有 dispatch observer 的路径跳过额外 JSON 解析。

普通整理、手动试写、历史候选、已确认参考的历史候选及同源对照透传同一执行上下文。每个任务仅持有一个原子标记；生成、复核、修复和最终复核均发出含画像请求时，也只计一次。同源对照仅画像组可设置标记，基础组完成后取消不能算画像已发送。本地校验失败、请求构建失败、请求前取消或期限到达均不设置标记。发起后收到错误、超时、取消或回退，仍计为客户端发起过，质量状态独立记录。

标记随终态回执保存；进行中的数量可晚于网络请求，不声称实时完整。取消后的请求 future 先退出，再读取终态标记；没有在网络回调内同步等待 SQLite 或增加新的模型请求。

## 数据与面板

保留原事件的 `personalized` 布尔值作为快照选择，新增可选 `referenceDispatch`：

| 值 | 含义 | 进入已发起计数 |
| --- | --- | --- |
| 缺失／null | 旧记录，无法追溯实际发送 | 否 |
| `notStarted` + 进行中 | 已选择但发送状态尚待终态确认 | 否 |
| `notStarted` + 终态 | 本次未进入含画像请求的发送分支 | 否 |
| `started` | 已进入含画像 HTTP 请求的客户端发送分支 | 是 |
| `unknown` | 中断前没有保存发送证据，无法确定 | 否 |

重启时，旧未完成且已选择画像的 `notStarted` 事件转为失败并标记 `unknown`。不能因为终态未落盘，就把已发生过的请求断言为“没有发送”。旧缺失标记的事件始终未知；既有正文、原始来源、画像版本与显式评价不变。存储拒绝证据降级、终态事后升级、画像选择或身份变更。

主指标只统计有可核验证据的已记录普通任务；分母明确为已记录的全部普通整理任务。预览独立，场合分布仅普通整理，选择数量、旧记录未知、中断未知、进行中待确认分别可见。计数不表示质量收益，显式评价的分母仍是有效对照中实际评价的次数。

任何事件写入失败后，本次进程不再返回汇总，避免丢失回执却展示貌似完整的数量；后续成功写入不会重置。前端失败或重新读取时清除旧汇总，不在重试等待中恢复缓存数字。统计失败本身不删除识别稿或成稿，也不阻断普通整理。该失败标记仅在进程内；不能在重启后还原未写入的任务，因此从未把已记录分母描述为全部实际录音。

## 兼容性

桌面候选升级为 0.2.32，前端 0.4.29，SQLite schema 5。升级仅建立旧程序的版本屏障，保留旧事件 JSON 原字节，不从旧 true 值伪造发送证据。旧版 schema 4 程序不能重新打开已经升级的数据库；没有数据库降级功能。当前试用说明将明确这个边界，不安装或启动候选程序来修改真实用户数据库。
