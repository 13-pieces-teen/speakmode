# 0.2.28：转写传输与润色复核速度

日期：2026-10-22。基线为最新 `main` / `1e443ac`（0.2.27），候选桌面 0.2.28，前端仍为 0.4.26。

这轮判断的是：在保留来源、逐项复核、局部修补、截止时间与交付约束时，能否缩短结束口述后的润色等待。真实麦克风到宿主输入全流程未测量。

## 生产变更

- 北京 `qwen3.8-flash` 的 minimum 复核用固定顺序的五项数组，替代重复的 checks 字段名。coverage / facts / scope / intent / cleanup 的任务说明不变；五项全部 pass、issues 为空才可 accept。
- 严格要求五项、合法状态、总判断一致、问题引文对应来源，仍绑定原来的 source / draft / mode。缺项、额外字段、重复字段、跨版本响应或失败状态不能授权成稿。旧命名字段响应保留兼容；未请求数组的路径不接受数组。
- 未更换生成模型、生成提示或期限，没有跳过独立复核或增加自动重试。局部修补后仍需新的完整复核，原有可证明的重复句头删除例外保持。
- 其他模型/地域、实验英文特性和显式英文输出上下文继续使用原格式，不能从本轮数据推断其提速。
- 两个实时 ASR 适配器启用 TCP_NODELAY。仍按原顺序发送全部音频及 finish，等待最终确认；没有缩短 VAD、结束确认或完整来源检查。

## 固定文本云端对照

使用现有凭据，只读 provider_config 配置，不读取历史、录音或宿主文本。实际 40 次客户端请求，实验上限 58，调用方不自动重试。先写计划和请求/来源哈希，再执行。

复核部分为 9 个独立合成案例及 4 个重复案例，共 13 对；每对交替先后次序，重复案例反转次序。两臂使用同一 source、draft、模式及事实检查，唯一区别是复核响应格式。

| 指标 | 命名字段 | 五项数组 |
| --- | ---: | ---: |
| 复核响应解析 | 13/13 | 13/13 |
| 符合预先标签 | 12/13 | 12/13 |
| 复核耗时中位数 | 1,812 ms | 776 ms |
| completion tokens 中位数 | 57 | 42 |

13 对判断全部一致；复核中位耗时降低约 57%。这不是 13 个独立质量样本，也不是服务端计费或真实用户速度结论。

完整润色部分交替比较四个场合，走实际生成、准入、复核、修补和同一绝对期限路径，均给 20 秒实验上限。没有模拟 HTTP 延迟。

| 场合 | 命名字段耗时 | 五项数组耗时 | 两臂结果 |
| --- | ---: | ---: | --- |
| 聊天改口 | 1,098 ms | 755 ms | 均被既有本地准入拦截，不能计为成功提速 |
| 文档进展 | 3,690 ms | 2,949 ms | 均通过 |
| 技术约束 | 2,350 ms | 2,478 ms | 均通过；数组臂生成阶段较慢抵消复核收益 |
| 邮件沟通 | 3,027 ms | 1,973 ms | 均通过 |

完整润色均为 3/4 通过。仅对三个两臂都通过的案例计算：中位数 3.03→2.48 秒，约减少 18.1%；其中两对总耗时下降，一对略有上升。所有实验来源保持不变。数据量小，网络及生成波动仍会影响结果，不能推成所有口述均快 18%。

## 保留的问题

- “嗯，呃，我我今天，嗯，准备准备……”未清理的草稿被两种复核格式都误判为通过。更短响应没有解决这个既有自然度漏检。
- 聊天“明天下午三点，不对，四点”的正确整理，被两臂既有本地准入同时拦截。没有为追求速度绕过该检查。
- TCP_NODELAY 已通过自有回环连接读回实际 socket 属性；尚无真实 ASR 云端成对时延数据，不能量化它的收益。
- 没有真人录音、快捷键、Windows 焦点、安装升级或跨应用输入验收；固定文本润色时间不包含这些阶段。
