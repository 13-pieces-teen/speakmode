# 0.2.10 自动听写：整理链路与模型对照

日期：2026-10-10。桌面 0.2.10 / 前端 0.4.9。**最终决定：交付限定的校验误拦修复，整段新协议与 3.8 Flash 组合不升为默认。** 预留集未确认收益；已有模型设置与 Mode 契约保持。

## 本轮问题与改动

用户给出的 Typeless 对照涉及三个不同问题：识别错词、整理质量，以及正确整理被后续检查拒绝。本轮处理后两项，不将文本编辑实验称为音频识别率提升。

1. 实验候选为 Auto 无个人规则的整段输出协议，模型只返回呈现方式与正文。程序绑定完整识别来源，不再要求模型同时生成分片范围。来源仍不可修改，对照、恢复与撤销保留；来源对应精度为整段。最终未启用为生产默认。
2. 实验提示要求清理无意义的“呃、嗯”、废弃起句及重复表达，保留有意义的语气、问句、条件和不确定性。明确改口只替换被纠正的部分；含糊的替换不猜。这是候选目标，不能视作已在日常口述中稳定达成。
3. 完成录音开始时冻结词典到整理层的接口准备，仅实验候选提供来源已命中的标准拼写。例如 `typeless → Typeless`，不将 `swing mode` 猜成 SpeakMode。最多 32 条、总计 1024 字符；代码、路径和引用保持边界。生产旧提示不发送这个字段，不能称日常口述已获得该项提升。
4. 修正“区别/差别”中“别”的误判、有限语气停顿造成的数量作用域误判；明确数字改口与撤回说明仅修改校验分析视图，原识别稿不变。补充“下午两点前”等明确整点的检查。
5. 超时、格式错误或校验拒绝继续沿用 0.2.9 的完整识别稿回退和一次性输入；不自动打开主面板，也不在成稿输入后补一次粘贴。

## 证据方法

开发输入为 8 条已冻结脚本和 4 条专项样例。脚本被分成合成 ASR 文本片段，不包含自然人声、实际采音或 Typeless 运行结果。baseline 始终使用原 Qwen Flash 配置与旧提示；candidate 使用新协议、提示、命中词典及指定模型。两臂使用同轮校验器，因此不是安装版 0.2.9 与新版的完整端到端对比，也不能把组合收益全部归因于模型。

每轮 24 次真实云端调用，AB/BA 交替，不重试挑结果。v1 一轮、v2 三个模型各一轮、v3 一轮，共 120 次开发请求。另预留 4 条脚本，每条两次、每次两臂，最多 16 次。冻结 v3 后不根据预留成绩修改提示或语义检查。

每轮候选与预计回退正文去重、隐藏模型/实验臂和解析状态后，由另一 Agent 按忠实性、清理、可读性、口吻、专名五个维度判定，并另列关键错误。这里的“完整可用”要求五项全部通过，属于独立 Agent 评审，不是真人盲评或听写准确率。

预计交付按现有短口述 5 秒、长口述 20 秒预算计算；它不是实际 Windows 输入回执。所有请求都计入分母。原回执、评审和失败证据保存在本机 `output/validation/automatic-dictation-0.2.10`，不读取或导出个人历史/词库/Key。

| 候选模型（各 12 次） | 生成稿完整可用 | 接受且完整可用 | 接受的关键错误 | 云响应 P50 / P95 |
| --- | ---: | ---: | ---: | ---: |

| Qwen Plus | 9 | 8 | 2 | 1385.5 / 2830.95 ms |
| Qwen 3.8 Flash | 10 | 9 | 0 | 1006.5 / 1993.2 ms |

3.8 Flash 是本轮质量与耗时折中更好的候选，并非本轮最快或全市场最优。三模型批次分时执行、每模型样本有限，不能推导普遍延迟差异。更大的 Plus 并未在这些任务中稳定胜出。v1 未启用，全部旧结果保留。

采用同一非思考设置、温度 0.2、JSON object 协议和最大 8192 输出 token，没有给某一个模型额外工具或重试。公开接口支持不等于本产品的质量结论：[Qwen Flash](https://help.aliyun.com/zh/model-studio/qwen-flash)、[Qwen Plus](https://help.aliyun.com/zh/model-studio/qwen-plus)、[Qwen 3.8 Flash](https://help.aliyun.com/zh/model-studio/qwen3-8-flash)、[结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。

## v3 最终开发轮

v3 增加程序抽取的有限保留线索，要求保留未撤回的中文数量短语及个人判断、问句；结合限定的校验修复，最终开发轮结果如下。

| 指标（每臂 12 次） | 旧提示 / Flash | v3 / 3.8 Flash |
| --- | ---: | ---: |
| 生成稿完整可用 | 7 | 9 |
| 通过校验 | 9 | 11 |
| 接受且完整可用 / 预计最终完整可用 | 5 | 9 |
| 正确完整候选被拒绝 | 2 | 0 |
| 被接受的关键错误 | 1 | 0 |
| 预计识别稿回退 | 3 | 1 |
| 云响应 P50 / P95 | 924.5 / 1606.35 ms | 836.5 / 1356.8 ms |

该轮旧提示产生过将“帮我记进评审笔记”改成“已记入”的错误，新候选未出现评审标出的关键错误。一次有限评审没有证明语义绝不改变。

用户给出的原句在新候选中被接受为：

> 你好啊，就是刚刚同样的一段话，我现在用这个 Typeless 还有我们的 swing mode 一起用，看一下两者的一个区别。

它清理了“呃、嗯”，规范了已命中词典的 Typeless；未知音译 `swing mode` 原样保留。该例不能证明音频中正确产品名已被识别。

尚存 D03 改口限制：模型虽然将三个麦克风改为五个，仍复述“前面三个是我说错了”；校验拒绝再次引入撤回数字，预计交付回退为完整识别稿。这次未关闭检查或追加重试来刷高分数。

## 预留验证与最终选择

冻结 v3 后完成 4 条预留脚本 × 2 次 × 2 臂，16/16 云请求返回；未追加重试、修改提示或放宽语义检查。最初调用在请求前因工具将 `holdout` 与冻结语料标签 `holdout_reserved` 混淆而退出；只修正工具元数据映射并补自测，语料字节未改，该次没有云调用。

| 指标（每臂 8 次，4 个不同输入） | 旧提示 / Flash | v3 / 3.8 Flash |
| --- | ---: | ---: |
| 生成稿完整可用 | 7 | 3 |
| 通过校验 | 3 | 6 |
| 接受且完整可用 / 预计最终完整可用 | 3 | 3 |
| 正确完整候选被拒绝 | 4 | 0 |
| 被接受的关键错误 | 0 | 0 |
| 预计识别稿回退 | 5 | 2 |
| 云响应 P50 / P95 | 1133 / 1408.25 ms | 1168.5 / 1701.8 ms |

候选更常通过校验，却没有增加最终完整可用结果，生成文本的清理完成度反而下降。不能用“接受 3→6”代替用户感知的质量提升。4 条脚本也不足以计算稳定的一般任务通过率，重复调用不是更多独立用户样本。

复核评分依据后，候选 5 次 `cleanup=false` 全部涉及仍保留“啊”：H01 的“自动模式啊”（两次）、H02 的“先别改接口啊”（一次）、H04 的“完全没用啊”（两次）。H04 其实已正确处理数量改口和重复表达，后来仍被数值检查拒绝。因此不能写成“模型完全不会整理”。“啊”有时承载情绪或强调，这项评分存在主观边界；原用户认可的对照也保留“你好啊”。本轮保留原评分，不为凑收益改分，同时不把它解读为客观证明 3.8 模型更差。需要人工偏好和修改成本验证这一边界；仅靠本轮 Agent 全通过阈值不足以证明值得迁移默认。

因此没有启用候选协议、迁移默认模型或改写用户配置。`AUTOMATIC_PROTOCOL_PROMOTED=false`，即使手动选择 3.8 Flash，生产仍用原 Mode 契约。保留 136 次云端实验的全部回执与独立 Agent 评审，作为下一轮“提示过于保守”和“正确候选误拒”的诊断依据；原 Typeless 音频实验 CSV 仍为 NOT_RUN。
