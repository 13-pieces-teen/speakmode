# 0.2.9 交付连续性与微整理验证

日期：2026-10-10。基线为桌面 0.2.8 / 前端 0.4.7 的本地工作树，新版为 0.2.9 / 0.4.8。实现范围见[版本方案](../plans/delivery-first-0.2.9.md)。

## 证据口径

本轮分开测试协调器/SQLite、合成 React 交互、真实 Windows 已知文本输入、真实云端合成文本整理。不把任何一种结果改称真人听写准确率或完整 stop-to-paste 验收。

云端只读取用户已配置的 provider_config 和系统凭据，不读取个人历史或上传真实口述。所有请求来自入库冻结合成语料；不将凭据、个人配置、历史数据库或原始服务端标识入库。原始回执、失败记录及截图保留在本机 `output/validation/delivery-first-0.2.9`。

## 交付逻辑与校验器

- 完整识别稿已经 checkpoint 后，超时、网络/服务错误、响应格式错误及事实检查拒绝均可选择 sourceFallback。仍须先保存版本，再取得一次性输入许可。
- 取消、换会话、迟到响应、待提交来源、未完整来源、撤销自动输入资格、非初次口述、保存失败、重复派发均有专门回归。回退不生成“整理通过”诊断事件。
- 真实录音窗口的命令白名单原本未包含前端新调用的复制命令。本轮新增当前会话专用路径，拒绝历史选择器、过期 generation、待派发和取消，避免浏览器模拟通过而桌面按钮实际 forbidden。
- 扩展校验器探针 **64/64** 符合预期。旧 32 例中的 5 个误拦已经消除；明确数量、单位、版本、否定仍受检查。保留旧 `27/32` 回执，不能据此计算日常误拦率。
- 首轮全库回归发现中文“十点十分”的既有解析错误，补严格中文/ASCII 时刻规则后第二轮 **537 passed / 0 failed / 3 ignored**。这仍早于最终复制门控与等待策略测试，最终全库结果在发行表登记。

## 云端微整理 A/B：144 请求

固定 24 条输入（12 开发、12 确认）× Light / Structure / Auto × 两个提示臂。两臂同为用户配置的 Qwen Flash、相同来源/个人规则/温度/输出契约，交错执行，不用重试替换失败结果。144/144 得到可读取响应。

123 份唯一候选以隐藏 arm 的顺序交由另一 Agent 全文评分，映射回 144 调用。评分包含内容保真、清理完成、模式排版、自动分流、个人规则以及关键错误；这是独立 Agent 复核，不是人类盲评。重复模式响应不是独立用户样本。

| 指标（每臂 72 次） | 原提示 | 微整理候选 |
| --- | ---: | ---: |
| 生成稿全部任务维度通过 | 35 | 39 |
| 通过校验且全部任务维度通过 | 25 | 29 |
| 校验器接受 | 52 | 51 |
| 内容保真通过 | 57 | 52 |
| 清理完成 | 56 | 65 |
| 生成稿关键错误 | 6 | 6 |
| 校验器已放行的关键错误 | 2 | 1 |
| Light 完整可采用 / 24 | 10 | 13 |
| Structure 完整可采用 / 24 | 8 | 5 |
| Auto 完整可采用 / 24 | 7 | 11 |
| 云响应 P50 / P95（ms） | 630.5 / 951 | 612 / 826 |

候选少了口头冗余，但遗漏主观归属、限定、补充状态等更频繁。仅凭清理 56→65 或完整采用 25→29，不足以宣布整体质量胜出；Structure 也退步。它没有直接成为全部 Mode 的生产默认。

144 份响应由修复中文时刻后的最终 parser 重新离线解析，接受状态未变化；原云端回执和初版评分保留。2/3/5 秒的回顾性截断统计相同，因为这些短请求均在 2 秒内完成。它们不包含 ASR、保存、输入，也没有冷连接/弱网/长输入代表性。5 秒短口述预算是留余量的工程取舍，另由协调器超时测试验证实际 fallback 行为。

关键错误仍包括跨分片否定的误读、含糊改口被猜测、引用样本文字变成正文指令及丢失“导出尚未测试”的状态。有限规则不能证明完整语义一致；本版没有放宽所有检查来提高接受率。

## 更强模型诊断与最终选型

补充同冻结语料、同微整理提示的 Qwen Plus 诊断臂，**72/72** 返回，零服务失败、零重试。全轮合计 **216 次云请求**。原始 144 次成绩未改写；两模型分时执行，不是随机交错的速度实验，也不是新的留出确认。

第二轮将两模型共 144 响应去重为 124 份隐藏模型身份的候选；76 份与首轮逐字相同且 rubric 相同，沿用原判定；另一 Agent 独立审阅新增 48 份。评分后才联结模型与 parser 结果。

| 指标（每模型 72 次，同微整理提示） | Flash | Plus |
| --- | ---: | ---: |
| 生成稿全部任务维度通过 | 39 | 40 |
| 通过校验且全部任务维度通过 | 29 | 30 |
| 校验器接受 | 51 | 53 |
| 内容保真通过 | 52 | 57 |
| 清理完成 | 65 | 63 |
| 生成稿关键错误 | 6 | 4 |
| 校验器放行的关键错误 | 1 | 0 |
| Light / Structure / Auto 完整可采用（各 24） | 13 / 5 / 11 | 13 / 7 / 10 |
| 云响应 P50 / P95（ms） | 612 / 826 | 1273 / 1968 |
| 云响应 ≤2 秒 / ≤3 秒 / ≤5 秒 | 72 / 72 / 72 | 70 / 72 / 72 |

Plus 最长 2249 ms，仍在本版短口述 5 秒预算内。两臂输入 token 均 61,212，输出 token 分别 3,421 / 3,084；这是服务端报告的用量，不能按 token 总数直接推断同价或实际账单。

**最终选择：生产默认继续使用原 Flash 配置及 `mode-contract-v1`。** Plus＋候选是本次三个组合中完整可采用数最高的组合（30/72，原版 25/72），但同候选 Flash 相比只增加 1 条完整可采用任务，耗时明显增加，自动分流和清理并非全面提升。它仍产生 3 次歧义改口和 1 次跨分片否定关键错误（本轮均被 parser 拦截）。这不支持宣布稳定达到微整理目标，也不构成全部模型的最优结论。

另一个残留问题是 **正确清理被检查拒绝**：Plus 已正确生成的日期改口及指定人物份数改口仍有被拒绝案例。该臂 19 次拒绝均为 `rewrite_meaning_risk`，但不能把全部 19 次都算误拒。本版先自动用识别稿继续交付，未临时关闭 guard 或在同批语料上反复改规则提高成绩。后续需要独立验证这些规则边界。

研究候选只由显式实验入口调用，未改变用户配置、生产请求默认或凭据。真实接口兼容性核对参考：[百炼 OpenAI 兼容接口](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)、[结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。模型公开接口支持不代表本产品质量已经达标。
