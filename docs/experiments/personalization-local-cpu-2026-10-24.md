# 个性化本地准备耗时与验收边界 · 2026-10-24

本记录补充 PRD §9.2 的本地性能证据。画像设置、协议与统计的工程检查不能替代真实成稿质量。用户本轮初步反馈“都还可以”，同时报告微信自动输入失败、手动 Ctrl+V 可用；尚无逐任务识别稿、成稿及人工目标稿，不能据此计算六任务采用率或编辑负担。既有八格分离复核实验保持首个无效响应后停止的状态，本轮不追加云端调用。

## 测量方法

显式离线入口为 `app/src-tauri/examples/personalization_local_cpu_lab.rs`。使用 release 构建，直接调用现有公开生产 API，不复制整理逻辑、不打开用户数据库、不读取凭据、不构造网络客户端。固定合成源文和原文直通草稿不代表模型输出或语义通过。

同一技术场合、语言、服务配置、词典和完整源文，配对比较仅关闭／启用画像。两组均使用显式 WritingContext，因此测量不含路径切换引起的模型调用差异。源文长度为 400、800、3000、8000、80000 个 Unicode 字符；普通画像、接近 1200 字符预算的画像及含 JSON 转义字符的近上限画像各一份。预算按真实 freeze 的整字段选择计算，不手工补满请求。最大配置有三个身份，但只发送所选身份。

共 15 组，每组预热 20 对、正式测量 200 对，组内交替先后顺序并错开组间起始顺序。保留所有原始纳秒值及有符号的逐对差值，不把负差值截成零。p50／p95 使用 nearest-rank；`p95(每对启用耗时－关闭耗时)` 与两臂 p95 相减分别报告，二者不混用。

三项主窗口为画像 freeze、生成请求准备、复核请求准备，合计为三个窗口之和。API 内部的来源／草稿／配置绑定及 JSON 数据准备计入；另测的 provider_data 投影只作诊断，避免重复加入总数。使用 Instant 经过时间，包含操作系统调度，不是硬件 CPU 周期计数。

未测量：返回后校验、数据库统计写入、AppHub 锁、IPC、UI、宿主上下文采集、HTTP 最终发送与序列化、模型推理、录音及目标应用交付。该组件测量即使低于 30ms，也不足以宣告完整“新增本地处理 p95≤30ms”门槛通过，更不能说明在线 p95 增幅≤10%。

## 同轮邮件与复核修正

用户确认邮件应省去明确的起草指令。原提示允许省略，但格式锚点和有限疑问类别检查仍要求保留“帮我分段回邮件”或“能不能帮我回邮件”，导致合法正文在独立复核前回退。

现在只对有效 Email 场合、第一来源条目开头的六种完整前缀建立精确 UTF-8 范围授权：能不能帮我分段回邮件／帮我分段回邮件／能不能帮我回邮件／帮我回邮件／帮我写封邮件／帮我回一下。紧随其后必须是逗号、冒号、分号或问号及实质正文。引用、代码、否定、报告原话、带材料细节、非开头或跨片段形式不由该有限检查授权。

本地请求类别只排除授权范围内的锚点；数值、日期、字面量继续核对完整来源。格式式前缀还保护其后第一句的具体材料。三阶段模型请求仍包含完整 sourceText，来源 ID、原始识别和绑定不改；重复附加上下文会替换旧锚点，避免重新要求包装词。独立复核仍是硬门槛，任意材料名称或关系的保真不由这些有限规则证明。显式 Email 的手动候选也经过独立复核，其他手动路径保留原有严格关系检查。修复授权绑定完整上下文及请求消息，只允许原先选定的局部范围变动。

Minimum 中文提示补齐既有解析器要求：reason 非空白、1–100 Unicode 字符；两段引文非空白、1–80 字符且分别逐字来自原文／草稿。解析器未放宽，五项全部通过及最多两处问题的提示不变。中文 named 为 `minimum-review-v5`，ordered 为 `minimum-review-ordered-v2`；英文仍为原 v3/v4。分离实验提示同步至 v2，其精确替换仍失败即停止，旧冻结 fixture 和失败批次不改、不续跑。

最终静止源码快照的完整 Rust library 检查为 **1052 passed、0 failed、4 ignored**，42.73 秒，退出 0，缓存 11.862 GiB、预算无违规。证据 `output/personalization-email-native-final-tests-20261024.log`。新增 14 项包含 Unicode 边界、协议精确匹配、授权正反例、全来源四阶段、条件／问题／数值／代码损失拒绝及修复绑定；脚本模型结果不能证明真实模型质量。之前同为 1052 通过的检查另存，最终检查用于排除编辑与编译重叠。
