# SpeakMode 0.1.5：个人词典与采音稳定性

维护日期：2026-10-08。基线为 Git `e80ce224cf91d88ff401740a9d71d8609c9f3a68` 的桌面 0.1.4。当前状态：源码、合成基准、界面及 release/NSIS 验证完成；已补充固定 TTS 的真实云端对比、五轮真实设备采音和受控输入实验，真实人声/完整用户流程待测。范围只有专有词提示和采音回调，沿用现有 Mode、右 Alt 开始/结束、长停顿、来源对照与输入路径。

## 最新实测与下一轮优先级

以下保留 0.1.5 实验结束时的判断；后续修复已实施，见[0.1.6 方案](voice-0.1.6.md)和[独立复测](../experiments/voice-repair-0.1.6-2026-10-08.md)。原失败、指标和验收边界未改写。

详见[2026-10-08 真实实验报告](../experiments/voice-real-lab-2026-10-08.md)。词典在固定五词音频中两次均从 1/5→5/5；这确认该样本上的识别增量，不推断一般人声效果。五轮真实 CPAL/WASAPI 采音均完整，但没有旧版硬件对照，不能写成稳定性提升率。

实测揭示整理瓶颈：24 次中 12 次来源覆盖不足；另有两份已通过映射的结构稿遗漏时间限定“今天”。下一版优先修复来源映射表示/校验和关键限定保留，再用同一冻结语料复测。不能通过直接给缺失来源补 ID、放宽来源覆盖或把失败成稿自动交付来提升表面成功率。本轮只做实验，产品修复未实施。

## 增量与验收口径

| 项目 | 0.1.4 → 0.1.5 | 可以验证的增量 | 不据此声称的结果 |
| --- | --- | --- | --- |
| V1 个人词典 | 无词库 → 手动新增、编辑、删除、搜索及多行批量添加；SQLite 持久化 | 重启保留、去重、上限、并发冲突、取消及升级保留原数据 | 自动学习用户词汇、每个词都能正确识别 |
| V2 识别上下文 | ASR 仅设置语言 → 非空词库写入 `corpus.text` | 测试服务器收到正确上下文；录音起点冻结词库，重试沿用同一份 | 专有词实际命中率、中文 CER 或云端等待时间已经改善 |
| A1 回调缓存 | 每个采音回调创建 mono Vec → 启动时预分配、回调复用有界缓存 | 同样合成音频的 callback-owned 分配数与耗时；格式/声道/顺序一致性 | CPAL/WASAPI/整个语音链路零分配、真实设备不再丢音 |
| A2 停止与压力 | 保留已有明确溢出和尾音排空 → 验证缓存回收、大回调拆分及停止边界 | 满池/预算/断开不静默丢数据，结束后尾帧顺序与原契约一致 | 真实硬件/驱动/CPU 压力的稳定性验收已完成 |

词典是识别阶段的上下文提示，不是成稿里的字符串强制替换，也不加入 Mode 整理 prompt。该字段由[百炼实时 ASR 官方协议](https://help.aliyun.com/en/model-studio/qwen-asr-realtime-client-events)支持。词条随录音请求发送到用户所配置的百炼地域；Key 保持系统凭据管理方式。首版不从用户历史自动收集词条。

## 功能规则

- 主窗口提供词典，录音浮层不读取完整词库；正在录音时的词典更改从下一次录音生效。
- 最多 200 条，每条最多 80 个 Unicode scalar；上下文含编码后词表总计不超过 4,000 UTF-8 bytes。
- NFKC + Unicode casefold 去重，保留原拼写；批量添加是原子操作，重复项不覆盖，整批无变化不增加版本。
- 使用 `expectedVersion` 防止覆盖别处的修改；失败显示原因并保留草稿，刷新后由用户重试。
- SQLite 迁移只添加词典表；偏好、Mode 和历史继续保留。异步取消遵循原 DB worker 的提交仲裁。
- 采音仍为默认设备 WASAPI → mono → 16 kHz PCM16 → 100 ms 帧，保持手动结束；本批不改变 VAD、降噪或增益。
- 启动时预分配有界缓存，回调使用非阻塞队列。保留 2 秒原始样本预算和 64 个缓存块；超大设备回调按缓存容量拆分，不增加无界缓冲。

## 本地验证

统一 TypeScript/Vite、前端 helper、桌面 Rust 回归后构建独立 0.1.5 release/NSIS。测量使用非私密合成音频和临时数据库，不打开麦克风、不读取用户 Key、不调用云模型。自动化 UI 的模拟桌面接口只属于测试；生产浏览器页不生成示例词条。

回调基准须记录采样率、声道数、每回调样本量、次数、构建 profile、allocator 统计范围及 P50/P95。全套回归不执行 ignored 基准；它单独运行，避免并行测试污染。完整结果在验证完成后填写，并保留失败尝试。

### 已执行结果

- Windows desktop Rust 全库：319 passed、0 failed、2 ignored。比基线增加 30 项：词典/迁移/IPC/ASR wire 17 项、采音池与停止/静音/格式/分配 13 项。忽略项为原有 maintenance child 与新增独立基准；基准另外执行并通过。
- 前端 TypeScript/Vite 与五个 helper：40 项通过（已有 27 项 + 词典 13 项）。既有 Radix `use client` 与 bundle size 警告仍存在。
- 隔离 UI 模拟接口验证新增、批量去重、搜索、编辑、删除、重复错误、容量错误、CAS 保留草稿及重试、保存中导航拦截、保存相同词条 no-op。720×560 与 1220×820 下 200 条词库含长词条，文档横向宽度分别为 720/1220，文字与操作列重叠数均为 0。此验证不替代真实 WebView IPC 或云端识别。
- SQLite v1→v2 用受控旧数据 fixture 验证偏好、Mode、历史、来源及使用量保留，另测重开后词库保留；没有读取或迁移用户真实数据库。
- release/NSIS 构建退出 0，独立保存程序与 `SpeakMode_0.1.5_x64-setup.exe`；142 个构建输入前后 SHA-256 相同，EXE/installer ProductVersion 均为 0.1.5。没有执行安装/升级/卸载，也没有触碰用户运行配置。

Release profile 合成采音基准：48 kHz；每场景预热 1,000 次，测量 20,000 次；同一线程轮流执行原回调和新回调并及时排空。耗时包含分配统计代理开销，不含 CPAL/WASAPI、worker/重采样、系统调度和云端。

| 场景 | 回调自身分配：旧 → 新 | P50：旧 → 新 | P95：旧 → 新 |
| --- | --- | --- | --- |
| f32 mono，480 samples／10 ms | 20,000 → 0 | 0.5 → 0.5 µs | 0.5 → 0.6 µs |
| i16 stereo，480 mono frames／10 ms | 20,000 → 0 | 0.7 → 0.8 µs | 0.8 → 0.8 µs |
| i16 stereo，4096 mono frames | 20,000 → 0 | 5.4 → 5.9 µs | 5.8 → 6.3 µs |

本次测量没有显示回调速度提升。已测增量是去掉回调自身的动态分配；代价为启动时预分配约 384,000 bytes／48 kHz，及上述小幅耗时增加。减少内存分配对真实压力下丢音/抖动的收益仍是待验证的假设，不把它写成已完成的稳定性百分比。

## 实际使用验证

1. 选 10 个自己常用的项目名/人名/缩写，各放进自然句子，使用同设备、模型、地域，分别在空词典和有词典下读相同内容。每组至少重复 3 次并交错顺序，记录失败/超时，不只挑成功例。
2. 分别统计识别稿中的专有词正确数/总出现数、非词典词误改数；另查最终成稿，区分 ASR 错误和 Mode 改写。不能只看整理后的文字估算识别率。
3. 说一句含否定/金额的句子，停顿 30 秒查资料后继续，末句结束立刻按右 Alt。核对首词、尾词、字幕、波形、完整录音和一次正确目标输入。
4. 记录冷启动、连续 3 次短口述、较长口述及日常 CPU 压力下的失败数与分阶段时延。首样本、首字幕、停止到 Ready 和宿主实际插入分别统计。
5. 断开/切换麦克风和服务失败应给出明确原因；确认取消后可再次开始，且不把不完整音频静默整理/输入。

真实准确率、设备稳定性和用户体验需要上述实测；合成基准和安装包构建只覆盖各自范围。
