# 0.2.11：默认整理模型与型号选择

日期：2026-10-11。用户在 0.2.10 实验报告之后明确要求替换默认模型，并可从列表选择其他型号。

本版将新建配置的整理模型设为 `qwen3.8-flash`，沿用已有非思考请求和 `mode-contract-v1`。没有启用 0.2.10 的整段实验提示；这次选择来自用户明确要求，不改写上一版的实验结论，也不宣称听写准确率已经提高。

## 使用与持久化

- 设置 → 云端服务 → 整理模型。默认型号排在首位，显示当前选中 ID、尚未保存状态和已保存的型号。
- 可选 Qwen 3.8 Flash、Qwen Flash、Qwen Plus、Qwen 3.7 Plus 及其 2026-05-26 快照。列表表示已接入协议，不表示所有账号均已开通或质量排名。
- 点击“保存服务配置”生效，后续口述使用新设置；当前录音使用开始时冻结的配置。更换模型无需重输同地域、同业务空间的 Key。
- 语音识别模型独立选择，保留原实时识别设置和适配器。
- 本地数据所有者启动时进行一次升级：仅将 `aliyun + beijing + qwen-flash` 替换成 `qwen3.8-flash`，原有其他型号或地域不改。
- 模型与配置版本、升级标记在同一 SQLite 事务写入；失败回滚。完成一次判断后不再覆盖用户后来手动选择的型号。新增标记表不提升既有 schema 版本。
- 保存提交成功后立即同步下一次录音使用的配置快照，即使无关的完整快照刷新失败，也不继续冻结旧型号；保存失败或版本冲突不会发布草稿配置。
- Key、历史、词典、偏好和音频不迁移；本轮开发与测试不直接写运行中的用户资料库。现有用户在启动新版时生效。

## 验证与交付

真实临时 SQLite 验证升级、再次启动、用户回选和事务失败；生产 React 配合隔离合成桥验证下拉选择、保存、版本冲突、失败保留与布局。完整 Rust 回归和 Windows EXE / NSIS 构建通过后登记结果。

这些验证不等于真实人声、新模型的账号连通性或实际停止到粘贴验收。上轮北京地域的 3.8 Flash 真实调用已完成，但本轮不额外消费云请求来声称新一轮质量提升。
