# 自动听写体验：SpeakMode 与 Typeless 对照计划

日期：2026-10-10。状态：样例分析与语料设计已完成；真人录音、同音频竞品实验、视频采样和效果验证均 **NOT_RUN**。本计划没有修改生产模型、提示词或自动输入流程。

## 产品目标

用户说完后得到自然、可直接使用的文字；用户不需要为了去除“呃、嗯”而选择 Mode，也不需要打开主面板重新整理。自动模式承担日常整理与自然排版。轻整理、结构等显式偏好可以保留，但不作为这轮默认体验验收的前置步骤。

基本清理应覆盖无意义停顿、重复起句、标点及明确改口；保留说话人的口吻、否定、条件、数量及不确定性。正常初次听写仍只向当前已验证的目标交付一次。整理异常时沿用 0.2.9 的完整识别稿回退，不新增先粘贴后偷偷覆盖的行为。

## 用户样例能说明什么

用户提交的是两份最终文本，没有原始音频、运行回执或同一录音的证明。它们可以用来发现体验问题，不能用来计算识别准确率或断定错误发生在哪个模型阶段。

| 维度 | SpeakMode 样例 | Typeless 样例 | 结论 |
| --- | --- | --- | --- |
| 无意义停顿 | 留下两处“呃”和一处“嗯” | 这些停顿词消失 | 本例 Typeless 的表面清理更充分 |
| 冗余连接 | “还有这个呃我们的” | “还有我们的” | 冗余可清理，但不能全局删除“这个”“就是”等词 |
| 专名书写 | typeless | Typeless | 要恢复专名的标准大小写，不是把所有英文大写 |
| 产品身份 | swing mode | Speed Mode | 两者都不是用户正在讨论的 SpeakMode；流畅不等于正确 |
| 句界与口吻 | “你好啊，” | “你好啊！” | 问候被单独断句更易读；没有音频，不能认定感叹号一定更忠实 |
| 残余赘述 | “两者它的一个区别” | 同样保留 | 竞品输出也不是唯一或完美的参考答案 |

仅按用户提供的上下文，一个保留闲聊口吻的目标示意是：“你好啊！刚刚同样的一段话，我现在用 Typeless 和我们的 SpeakMode 一起试一下，看看两者的区别。”这是人工示意，不是模型实测结果，也不是逐字金标准。

Typeless 官方介绍去填充词、去重复、处理临时改口及自动排版；这支持把这些能力视作产品预期，但不公开证明其内部模型或提示词实现。[官方介绍](https://www.typeless.com/)

## 当前代码核对与改进假设

核对对象是本地 0.2.9 源码，不能据此推断用户样例必然来自这一安装包。

| 当前证据 | 改进假设与验证方式 |
| --- | --- |
| `app/src-tauri/src/cloud/rewrite_baseline.rs` 已要求去无意义停顿、重复及放弃的起句，并处理明确改口 | 不能将问题简单归因于“没有写清理提示词”。对同一固定识别稿比较基线和候选，检查规则执行率 |
| `cloud/asr.rs` 的实时接口传入词典上下文；`cloud/asr_task.rs` 将适合的词条作为热词，其余在限额内作为上下文 | 专名错误应比较无新增词典与两端相同词典的条件，不能仅改文字整理就宣称改善了识别 |
| `cloud/rewrite.rs` 的整理请求包含 Mode、格式规则、来源条目和限定信息，没有独立的词典快照字段 | 候选可把相关专名的标准拼写提供给编辑层；不能无条件把相似读音强制改为 SpeakMode，更不能统一 `userID` 与 `userId` |
| 0.2.9 正常初次听写在可选整理失败后可交付完整识别稿 | 分别保存“识别稿→模型候选→校验结果→最终交付”。好的候选如果被误拦，用户仍看不到收益。未知阶段标为未知，不让用户诊断 |
| `scripts/voice-quality-lab.py` 的 CER 正规化会折叠大小写并忽略标点 | CER 保留为识别层辅助指标；增加精确专名书写、句界可读性与最终可用性评价，不用 CER 代替体验分 |

候选改动顺序：先补实际交付结果的归因，再试词典拼写贯通与自然口语清理，最后试长句的定向改口合并。一次主要改变一个因素，避免无法解释收益。自动排版默认自然句/段；真实多事项再分点，不把普通聊天全部包装成清单。

停止条件：候选出现新增的否定反转、条件放宽、主体错配、专名误替换或数量错误，不能用更短、更流畅抵消；先修复并用新留出样本复核。不得仅凭本次 12 条小样本宣布“达到 Typeless 水平”。

## 首批原创语料

材料是待真人录制的脚本，不是已经采集的自然语音，也不是视频原话。录制后需听原音重新标注实际说出的内容，不能把漏读的脚本文字当成 ASR 漏字。

- [开发集](../experiments/fixtures/dictation-experience-v1.dev.json)：D01–D08，8 条；用于诊断及候选开发。
- [预留验证集](../experiments/fixtures/dictation-experience-v1.holdout.json)：H01–H04，4 条；目前只预留，尚未冻结真实音频。不得用于逐条调提示词；看过运行结果后再修改方案，就要另采新验证集。
- [结果登记表](../experiments/fixtures/dictation-experience-v1.results-template.csv)：12 条 × 2 产品，共 24 行，均为 NOT_RUN；未测量字段留空。

| 编号 | 主要难点 |
| --- | --- |
| D01 | 简短反馈的语气词与委婉程度 |
| D02 | SpeakMode、Typeless、GitHub 及未经计时的主观感受 |
| D03 / D04 | “三个，不对五个”的即时改口，对照“原订三个又追加两个”的真实历史 |
| D05 / D06 | 没有书面确认时“不能先发”与“也可以先发”的最小条件对照 |

每条包含 mustPreserve、allowedCleanup、mustNotDo。允许多种正确成稿，不要求与某个参考句逐字相同。

## 同音频对照流程

1. 将首批脚本真人录成 WAV，保留自然停顿。另记设备、距离、环境、日期、实际时长及原始采样格式。固定送测文件，记录 PCM/WAV hash；不为某个产品单独删停顿、提音量或裁尾音。
2. 第一个条件 `native_default` 比较当前日常体验：SpeakMode 固定自动；Typeless 使用普通听写默认。记录两个产品的版本、语言、已有词典快照、可见个性化状态及同一个目标输入框。词典不同则该条件只说明日常体验，不能归因模型优劣。
3. 第二个可选条件 `matched_dictionary`：两端添加相同、与语料相关的标准词条后重测，不覆盖第一条件。无需删除用户原有词典；若无法隔离其影响，则明确记录残余差异。不能把完整标准答案或预留验证集内容塞进词典。
4. 同一文件依次送入两端，交替先后顺序 AB/BA。使用同一个空白输入框环境，每次恢复空白；不要两个软件同时抢同一快捷键。只计第一次结果；重跑单列，不取最佳结果。
5. 可选用虚拟音频设备将播放器输出送入两端选定的麦克风输入。VB-CABLE 官方说明其播放端输入会转发到录音端输出。[设备说明](https://vb-audio.com/Cable/) Typeless 支持选择输入设备，并提供听写时静音其他音频的设置；回放实验需要关闭会把测试音频静音的选项。[设置说明](https://www.typeless.com/help/quickstart/settings) 这只是待验证的实验接线方案，本次未安装驱动、改系统音频或执行回放。
6. 采集最终实际插入的文本、停录到出现结果的耗时，以及是否丢失、重复、错误目标输入。SpeakMode 可记录可观测的内部阶段；Typeless 没有暴露的内部 ASR/候选保持未知。应用报“已派发”不等于实际成功插入。
7. 隐藏产品名称、随机呈现最终文本，由人听原音核对事实，再评价可读性。记录修到可直接使用所需的时间，控制同一审稿人反复看到相同音频的学习效应。没有人工审稿或只有 Agent 审稿时如实标注。

原始录音与填写后的私有结果放到项目外层 `runtime/dictation-benchmark-2026-10-10/`，不加入公开仓库。已有 `.gitignore` 排除了 runtime 和音频；公开目录只保留原创脚本、空表及匿名汇总。

软件回放只能检查固定音频到文字/交付的表现，不能证明麦克风采集或轻语增强有效。轻语另做同一个人的真实轻声与正常音量采集，明确保持正常音调；不把缩小 WAV 音量当成全部真人轻语验收。

## 视频素材扩展

先完成原创语料，再补 4 段 30–90 秒的自然讲话：技术演示中的改口、多主体安排、带条件的问答，以及中英混合的产品讨论。选自己的视频或适合使用的来源，记录 URL/本地来源、作者、起止时间、使用依据和音频 hash；本次没有选定、下载或剪出视频。

剪辑保留一句话的完整前后关系，特别是后面的否定、补充或更正；不要在纠正之前截断。平台字幕只用作初稿，须听音修订。录制脚本、即兴自述、视频片段分组报告，不能混合为一个“真人准确率”。视频通常缺少真实个人词典和目标输入场景，也不能取代用户自己的口述。

## 评价与最终选择

主指标为最终交付的可直接使用率、关键语义错误数、人工修改时间和停止到实际输入的延迟。失败、超时及识别稿回退均留在全体样本分母中；不能只看成功整理的子集。无输入与输入了差文本分开记。

| 字段 | 登记口径 |
| --- | --- |
| criticalMeaningErrors | 人工确认的关键错误数：遗漏/篡改条件否定、数字、主体、时间、专名身份或新增事实；未审稿留空 |
| fillerCleanupScore | 0=明显残留干扰阅读；1=部分清理；2=无意义停顿和重复已清理且未误删有意义表达；源文本无清理机会填 N/A |
| readabilityScore | 0=断句/格式显著妨碍理解；1=可读但仍需修整；2=自然分句及排版 |
| tonePreservationScore | 0=立场/口吻明显改变；1=局部不自然；2=保留原有强度、委婉程度及语气 |
| properNameCasePass | true/false；无可评词项填 N/A，未评留空。大小写和专名身份错误分别在 notes 说明 |
| usableWithoutEdit | 人工确认无需改写即可使用的 true/false；语义错误或未交付必须 false；未运行/未评留空 |
| manualEditSeconds | 人工从收到结果到修成可用文本的实测时间；未测留空，不以字符编辑距离推算 |
| stopToInsertMs | 结束录音操作到目标里实际出现结果的实测耗时；未插入/未测留空，不拿云请求耗时替代 |
| finalOrigin / fallbackReason | SpeakMode 可观测时记录实际整理/识别稿及回退原因；Typeless 未暴露时不得猜测 |

不将这些分数简单加权掩盖语义失败。先报告严重错误和交付失败，再比较清理、标点、口吻与耗时；样本数、N/A 和未测项目必须同时显示。对成对例还要检查两条的事实/允许条件确实不同。

本仓库已有 [voice-quality-lab](../experiments/voice-quality-lab.md) 可在录音后冻结音频和参考，并登记回执。这里的 JSON 与 CSV 是录制和人工评审材料，不是它的 manifest，不能直接传给 `freeze`。适配时保留原 schema 校验；大小写、标点与手工修改时间作为本轮附加指标。未测的 Typeless 内部阶段不伪造成完整链路证据。

选择流程：开发集定位单项改进 → 冻结候选和实际录音 → 在未用于调参的语料上做默认体验对照 → 再确认真实麦克风及输入目标。当前没有足够证据选择新模型、宣布升级收益或更换生产默认。
