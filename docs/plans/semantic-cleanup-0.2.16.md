# 0.2.16：从词法阻断转向候选与语义复核

日期：2026-10-11。基线桌面 0.2.15 / 前端 0.4.14。

## 问题

连续三次真实口述反馈仍保留停顿词。最新元数据与用户给出的新来源一致（3 片、150 字），原因为 meaningRisk，停止至输出约 1978 ms。检查时应用已退出，不能声称核实了本次运行版本。逐句扩展有限数量规则未解决语义判断与自然整理的冲突，本轮不继续堆叠题材词或句式白名单。

## 候选流程

1. 保留不可变识别来源；模型生成完整整理稿，原有 Mode 和个人规则边界仍成立。
2. 来源完整性、JSON 格式、长度、模式和引用映射仍为硬约束；这些失败绝不交给复核放行。
3. 先比较明确数值、时间及限定类别；通过前置检查的每份候选都进行一次简短语义复核，比较信息、事实、条件/否定/不确定范围、意图和清理质量。旧词法检查只保留为实验对照，不能快速放行新流程的候选。开发例 D04 已证明旧检查也可能漏掉条件范围变化。
4. 复核只判断、不能改稿。只有严格、完整的接受结果才采用原候选；不确定、拒绝或请求失败均保持完整识别稿保底。原始来源不改写。
5. 两阶段共用现有总等待期限，取消会终止在途请求，结果只交付一次，迟到的复核不能二次粘贴。

本轮实测选择全段流畅整理 fluent-dictation-v1 + semantic-review-compact-v2。仅北京 / qwen3.8-flash / 默认自动（个人规则为空）启用；其他模型、地域、轻整理、结构和个人规则沿既有路径，配置不被自动改写。现有生产基线与历史实验接口保持可调用用于对照。

## 有限实验与发布门槛

- 本轮初始总请求预算上限 48，不重生成挑选结果。最初两次使用冻结生产/自然提示生成新样例；原请求保留，解析判定再用当前代码离线确认。
- 开发集验证协议与错误解析；独立 Agent 先冻结 14 个 source/draft 正反例，提示冻结后才使用预留集。预期答案不得进入模型请求。被放行的关键语义错误会阻止该复核方案发布。
- 复用已有用户样例的候选做复核，并对新生成及最终交付分别进行独立文字评审；不把旧响应回放当成新模型或 ASR 实验。
- 测量每份通过前置检查的候选均执行第二调用的总耗时和 5 秒预算内交付；不能仅用解析通过率判断提升。若实验达不到门槛，只保留实验结果，说明限制。
- 实现进入生产前，验证严格形状或明确事实前置检查失败不会请求复核、每份合法候选只复核一次、取消与总超时、拒绝/异常原稿保底、一次性输入、历史来源与恢复契约。成功路径由一次调用变为两次，共用原有截止时间。
- 保存完整失败与真实测量，更新方案和报告；通过后构建 EXE / NSIS，不改用户 Key、配置或历史，不代为停止/启动应用。

## 已测结果与选择

共 43 次云请求，无自动重试或挑选重生成。长引文复核 v1 在 8 例中全部被拒，单次 3.49–6.71 秒，淘汰并保留源码与原始响应。简短复核 v2 开发 7/8，遗漏一例原稿卡顿未清理；独立冻结预留集 14/14（7 可接受、7 有实质错误）。6 个完整流程使用 11 次调用，5 个通过前置检查与复核，在 1.69–2.29 秒内得到可用成稿；另一个长简历样例仍被前置检查拒绝。所有六稿独立文字评审：保真 6/6、去卡顿 6/6、排版及整体可用 5/6，长简历仍须改进分段。

选择范围：默认自动路径的实测增量足以接入；不声称复核能证明语义等价或日常错误率。长简历误拒、质量复核漏检、其他配置及真人音频/宿主输入仍为边界。本版不继续增加题材词白名单，不更换 ASR 模型，不修改录音或粘贴目标逻辑。
