# SpeakMode 0.2.0：听写质量升级

日期：2026-10-08。基线为0.1.9／前端0.3.4，提交 `8c95c36a685ce7bc7e0a4e2ca54b32cf95f16a1c`。本版桌面0.2.0／前端0.4.0，实际结果另记于[实验报告](../experiments/voice-0.2.0-2026-10-08.md)。

目标是减少反复改词、让结构整理更自然，并建立可复现的新旧模型比较。保持Windows、云端优先、右Alt开始／结束、现有Mode与来源恢复。Typeless公开行为作为目标参考，其具体模型或内部实现未知；本版不宣称达到或超过其准确率。

## 技术边界

- 新ASR：`run-task → task-started → PCM16二进制帧 → finish-task → task-finished`。收到ACK后才发音频；最终句和任务终态分开；partial不冒充SourceRevision。沿用取消、缓存回放节拍、帧序号和尾帧计数。
- 词典仍为最多200条、每条80 Unicode字符、总上下文4000 UTF-8 bytes。新接口即时词条按中文等非ASCII最多15字符／英文最多7词编码；更长条目进入每段400字符、最多5段的词典context，超过时明确拒绝，不悄悄截断。不采集应用文本、剪贴板或历史作为上下文。
- `revision.correctTerm`绑定会话、当前输出版本、单一Unicode范围、原文字和可选词典版本。数据库写入失败／取消／旧版本时两边都不发布；MemoryOnly只单独保存明确勾选的词条，正文仍在内存。修改后的成稿不重新自动派发给宿主。
- 整理保留原不可变来源，允许块内归类而不放开任意sourceRefs。有限检查无法识别所有新增行动、隐含语义、同义句或错误关联；保留对照与恢复。
- 表达偏好复用现有个人Mode，不新增暗中学习、账号、订阅或长期用户画像。

## 验证与发布门槛

1. 新行为先失败再实现；重点回归ACK、尾句、取消、断网、原子保存、冲突、MemoryOnly、恢复和一次输入。
2. 前端检查与生产React合成bridge验证：纠词、偏好、模型设置、窄窗口、既有恢复。与真实Windows输入验收分开。
3. 同一固定TTS运行旧／新ASR各四臂：A专名有／无词典，B改口及限定，C长停顿；总计最多8调用、零自动重试。另四个固定文本旧／新prompt最多8调用。原失败不覆盖，真人与Typeless对照仍未完成。
4. 全库测试、锁定依赖构建、EXE与NSIS版本／哈希检查，构建前后源码和第三方材料不漂移。
5. 默认识别与整理模型暂保留；候选接口通了不等于一般人声更准确。默认切换需真人试点、停止链路、模型可用性与延迟共同确认。

实际实验中初轮prompt出现事实示例污染，随后进行了两轮各4次Flash候选诊断和4次Plus诊断，分别使用新文件保存；并非自动重试或补跑覆盖失败。本轮合计8次ASR、20次整理请求。最终Plus四个已知案例核对通过，Flash连续日期改口仍存在限制；具体结果和否定同义词误拦修复见实验报告。未更改用户保存的模型配置。

本版不包含主动重识别成功稿、自动抓取宿主上下文、全局监听用户改字或每次双模型调用。真实麦克风噪声／声道优化继续根据实际失败录音评估。0.1.9的Codex／记事本／浏览器物理快捷键输入仍是独立待验收项。
