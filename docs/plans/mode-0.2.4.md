# SpeakMode 0.2.4：让整理方式有可检查的区别

2026-10-09。实施基线 `5d5047c`（桌面 0.2.3 / 前端 0.4.3）。本版为桌面 0.2.4 / 前端 0.4.4。优先回应用户对“整理效果与不同 Mode 的区别”的反馈。

**交付决策：** 两轮共 48 次合成文本云端诊断未证明候选规则能稳定保真并区分 Mode，因此普通口述、个人试用与双模式对比继续使用原有 `mode-contract-v1`。`mode-contract-v3` 保留为实验工具明确调用的候选，不成为默认。分片保留、对比、候选审阅及限定误拦修复进入本版。

## 本轮增量

| 之前 | 本版实施内容 | 验收依据 |
| --- | --- | --- |
| 模式区别主要由简短任务提示表达 | 实现并测试更明确的编辑任务契约；因质量门槛未达成保留在实验入口，生产沿用旧规则 | 两轮各 24 次固定输入同模型比较，失败保留；合法 JSON 不等于语义正确 |
| 历史试用将识别稿拼成单段 | 后端按 session/source revision 读取原始分片，保留 ID 和顺序 | 隔离数据库测试；过期、删除与冲突输入拒绝 |
| 一次只看一个试用结果 | 用户主动比较同一输入的内置轻整理与结构，显示两份结果 | 恰好两次串行云请求；取消、失败、迟到结果测试 |
| 换 Mode 的候选只有正文 | 按需对照生成时的当前稿与新候选，标明字符变化与长文本退化 | 冻结基线、过期不可采用、窄屏无溢出；采用仍为整个版本 |
| 缺少 Mode 专属的固定内容集 | 16 条人工开发样例，记录事实、条件、组织要求与可接受 Auto 结果 | 人工目标不冒充模型输出；独立保留实际实验失败 |

## 产品边界

保留自动、轻整理、结构和已有个人 Mode 名称及规则。正常录音仍一次整理，模型、ASR、自动输入和 SQLite schema 保持当前配置。内置比较只在用户点击时产生两次整理，不采用个人规则，不保存或自动输入试用结果。

轻整理保留叙述路径，清理口语冗余并写成自然文字；结构将有关的内容与后补说明归到同一主题，保留条件、否定、不确定性和步骤顺序。短而清楚的单句可以得到相同输出，不奖励无意义改写。

本轮不实施摘要扩写、屏幕读取、自动学习历史、第二次强制校对、任意局部采用候选或来源图迁移。现有局部恢复、撤销、录音快照及来源覆盖约定继续生效。

## 实现与验证顺序

1. 模式任务规则、prompt 版本和人工开发集。
2. 历史试用原始分片、同输入双模式比较及取消隔离。
3. 候选字符对照，明确冻结基线与整体高亮退化。
4. TypeScript/Vite、原生库、隔离浏览器及限定数量的合成文本云端诊断。
5. 共用 MSVC 缓存构建程序/安装包，保留输入摘要和测试收据。未进行的真人听写、安装升级及 HCI 任务单独列出。

真实结果维护于 [本版验证记录](../experiments/mode-0.2.4-2026-10-09.md)。效果门槛是模式任务完成情况提高且关键事实不退化；小样本诊断不提供总体准确率结论。

## 下一阶段的停止与进入条件

本次停止继续堆叠提示词或更换模型来掩盖结果。下一阶段先实验“有类型的组织结构＋本地呈现”：同一次请求明确段落、主题及顺序关系，保留当前连续来源范围；用独立留出集确认事实、主观归属、条件范围与真实组织差异，再决定是否切换默认。来源覆盖和字符差异仍不能证明语义正确。

单独的模型比较在任务契约冻结后进行，不把换模型的收益归给 Mode。任意局部采用、完整来源图、自动摘要和读取屏幕继续不属于这一轮。
