# SpeakMode 0.2.5：跨片段语义与交付计时

2026-10-09。实施基线 `df811f8`，桌面 0.2.4。目标桌面版本 0.2.5；前端无功能变更，package 保持 0.4.4。

## 本轮范围

本版落实语音工程路线中已有明确失败证据的部分：修复有限语义检查的跨片段上下文、更正目标和疑问句误拦，并补齐成稿到原生输入回执的计时。正常口述仍使用一次云端整理，保留 `mode-contract-v1`、默认模型、不可变识别稿及现有来源映射/局部恢复协议。

| 0.2.4 问题 | 本版增量 | 验收口径 |
| --- | --- | --- |
| ASR 分片被当成语义句，`不是` + `说…` 可能绑定到错误动作 | 增加有来源的有限分析视图，跨片段识别悬空限定；不重写识别原稿 | 正确合句接受，错接否定对象、断开的否定拒绝；原始来源不变 |
| `我说错了` 撤销紧邻一句，可能删除地点而没有撤销日期 | 只在明确旧值或唯一可确定目标上处理更正；含糊目标保守保留 | 日期变更后保留地点/条件；不同事项同类型值不能任意合并 |
| `能不能` 被当成否定，数值 `只有` 被当成必要条件 | 区分有限疑问与数量句式，保留问题及实际必要条件约束 | 正反样例分别评估误拦与漏拦，不能整体关闭检查 |
| 已有原生输入阶段事件，但缺少直接派生耗时 | 新增 ready→native receipt、stop→native receipt，导出兼容旧 schema | 无事件/逆序为 null；原生回执不冒充宿主实际插入 |

## 验证顺序与停止条件

1. 独立固定的合成正反回归集，以及现有来源/条件/取消/恢复原生库测试。
2. 离线重新解析上一轮冻结的 240 份真实云端响应。原始响应与原评分不修改；分别列出新放行和新拦截。此前未审阅的新放行不自动计为语义正确。
3. 复核状态发生变化的输出。新增的错误放行、原已接受且语义正确结果的新误拦，或来源恢复回归未解决时，不交付该实现。开发挑战集的剩余能力缺口必须单独列出，不能通过放宽评分或删除案例隐藏。
4. 前端构建、诊断导出兼容测试、共用 MSVC 缓存构建 EXE/NSIS，生成带哈希的交付记录。

本轮为确定性工程修复，不新增云调用。重放结果反映相同旧响应经过新检查的变化，不代表新模型生成质量、真实录音准确率或延迟提升。新的 protectedQualifiers 会随修复产生变化，其对新生成结果的影响仍需后续真实口述验证。

## 后续范围

`typed-flash` 继续保留在实验入口，尚不接入默认；需要解决完整语义、Mode 组织效果及逐句恢复兼容。连接中缓存预算、文件识别恢复接口、真实宿主插入确认留到独立小版本，避免同时改变识别与交付而无法归因。

实际增量、剩余限制与安装包见 [验证记录](../experiments/voice-0.2.5-2026-10-09.md)。
