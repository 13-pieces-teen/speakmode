# 0.2.15：减少重复数量表达造成的误回退

日期：2026-10-11。基线：桌面 0.2.14 / 前端 0.4.13。

## 问题与证据

已只读核对运行程序，路径及哈希匹配 0.2.14 发布包。最新历史来源与用户主动提供的游戏口述忽略标点、空白一致；记录为 `meaningRisk` 回退，停止至输出约 924 ms，不是超时。数据库没有保存被拒绝的模型响应，不能由元数据推断那次具体触发项。

对用户提供的原文新增两次同模型文字请求，生产基线和自然整理实验各一次。两份响应均已去掉明显停顿词，均被数量检查拒绝。有限数量检查将相邻重启中的两个“一个”当成独立事实，并缺乏对局部类型描述中“个/款”的区分。原始请求和正文存于仓库外。

## 实施边界

- 为数量出现建立局部对应：相邻重复数量必须有同一对象及候选保留数量的证据；不能把真实创建数量全部删掉。
- 局部类型关系允许有证据的分类词变化；不能全局将“个”“款”“种”视为相同单位，不能丢失类型、所属对象、否定或限定条件。
- 来源内容、引用与代码保持保护；含糊关系继续采用既有严格检查。
- 保持默认生产提示、模型、等待预算、原稿回退及一次性输入流程。明确列举的排版与停顿词清理分别评估，本轮不同时扩大自动路由规则。

## 验证计划

新增规则先记录失败测试，再实现与复验。独立 Agent 先冻结 12 条公开合成挑战（两种解析器及原文恒等控制共 48 项），再与实现对照。独立正文盲评不显示实验身份。

复用新样例的同两份响应做修复前后重判，保留原输出与耗时；继续回放上一版 2 条及更早 68 条留存响应，不能把回放称为新云实验或 ASR 测试。检查真实单片及合成分片的差异。云请求总上限 14，首次复现使用 2；额外请求仅在离线验证无法回答的必要问题上使用，不重生成挑选结果。

完整 Rust、评分工具、固定保护探针、现有 Mode 回归及分发构建必须执行。保留已知旧缺口，明确原生录音、实际粘贴及安装升级的未验收边界。构建 EXE / NSIS 并校验输入与分发哈希，不启动安装器或替换用户正在运行的程序。
