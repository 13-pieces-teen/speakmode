# 输入位置感知与场合成稿

本轮判断：同一浏览器里的聊天框和文档编辑器，能否得到更适用的成稿，并减少完成真实写作任务需要的人工改动。

## 产品合同

- 主选择为自动、聊天消息、文档写作、邮件沟通、技术沟通，以及用户定义的自定义场合。旧轻整理/结构保留历史身份，成为自定义表达组织偏好；不改写旧记录。
- 自动同时参考完整口述和输入位置。手动场合优先；自我介绍即使在聊天框也应保留连贯叙事。文档默认为自然段落，只有用户表达或实际内容需要时才分点。
- 输出语言与识别语言分开：跟随口述或英文成稿。识别事实、时态、数字、条件和未知专名仍需保留。
- 输入位置参考为可关闭、可按应用排除的功能。只采集当前可编辑控件标签及光标附近文本；标签160、前文1000、选区500、后文500字符。无整页、截图、标题、URL、剪贴板模拟复制。默认关闭；设置解释会发送给已配置的模型。
- 采集在停止录音后与 ASR 收尾并行进行，验证当前目标；超时、切换、密码/只读控件或不支持时丢弃参考。原始口述始终是事实来源；附近文本不授权执行指令、回答问题、增加事实或替换专名。
- 同一份冻结上下文用于生成和复核；沿用共同期限、取消、来源回退和单次投递。原始上下文只在本次处理内存保留，不进入历史或诊断。

## 实施与验证

1. 新增场合身份、兼容读取、输出语言与上下文设置，统一主窗和录音条选择。
2. 接入有界原生/UIA文本采集及停止目标校验，加入不可用/过期/排除/取消测试。
3. 将场合与局部上下文纳入生成、修复、复核；保留不可变来源和历史人工核对。
4. 自动测试覆盖配置迁移、同浏览器不同字段、显式覆盖、注入/事实污染、时态数字、取消超时与不重复投递。用真实 React 的浏览器交互验收设置与选择。
5. 新建独立文字评估，不复用既有耗尽预算。上限48次请求，最多12条路径、每条最多4次；鉴权或限流停止，不自动重试未知提交。固定合成用例、相同模型和期限，记录每次真实调用。验证聊天/文档配对、英文自我介绍、邮件、技术、恶意或冲突参考。所有结果包括失败都保留。已知事实错误或上下文注入不得算成功。
6. 在自建测试控件验证原生采集；构建可试用产物并提交源码 PR。测试、文字模型评估、原生控件与真实麦克风/日常使用分别报告，不能互相替代。

## 完成条件

代码路径、设置、界面和回归检查闭合；新场合确实传入模型，当前字段确实可采集；文字与受控本机验收结果可复查。对未测试的真实录音和复杂宿主保留明确边界。若文字评估未支持新的自动默认，则保留手动可试用能力，不把失败候选描述为已改善。

## 首轮评估后的修订

- 首轮文字测试已停止：23/48次请求、12路径，7/8新路径被管线接受，技术表达1条输出格式/模式检查失败。聊天与文档报告同文输出可能合理，但未证明场合收益；长自我介绍与邮件段落组织不足，不把7/8解释成质量提升。
- 新场合的组织布局改为 Auto：场合明确不等于强制 Light。自然段或列点由表达目的决定；旧 Light/Structure 与个人规则继续固定其组织合同。
- 后续验证独立预算最多16次、4条路径，协议v2。覆盖首轮技术失败、自我介绍分段、邮件分段和一条未见过的文档续写，保留全部失败；不重开已结束的首轮账本。
- 受控 Edge 首轮发现 UIA 范围跨出输入框，先修复边界夹取再复验。上下文不能越过当前控件，即使相邻字段属于同一页面。
- 原生提供者不可安全抢占，所以采用停止时采集，避免录音预取占用短录音的结束目标检查。最多600ms上下文/应用等待计入原有整理总期限。

## 第二轮结果与最后一轮定向验证

- v2 已停止：8/16 次请求、4 条路径。模型接受 4/4，人工完整验收 2/4：自我介绍正确分为三段，新文档正确区分完成情况与计划；邮件仍单段，技术稿漏掉口述中的列点请求而复核未发现。
- v3 将明确的口述排版请求作为来源绑定的保留片段并本地核对；邮件用实际 JSON 换行示例说明主题分段。保留全部 v1/v2 失败，不将模型接受率当质量成绩。
- 冻结 `situational-dictation-v3.followup.json`：两个已曝光问题与两个新样例（英文技术请求、邮件进展与安排），共4条路径、最多16次请求。早期预算不重开；最终结果分别报告管线接受、内容完整及场合呈现。
- 原生 Edge r2 的 23 项中 21 项通过，另外两项为空编辑器的 UIA 末尾字符。最初怀疑为 CR/LF；r3 逐字符证据实际确认为 U+FFFC 对象占位符，原假设不成立。只在 UIA 返回上下文时清除纯占位、将混合占位换为空格，保留真实文字与词界，不改变目标偏移或原稿。增加纯测试，并用严格空串判定复验。
- 交叉审阅要求将可选上下文与必要目标检查隔离为两个固定有界工作线程，防止上下文提供者卡住后阻止正常投递。普通目标捕获不再依赖可选书签的成功。

## 最终文字评估结论

v3 已停止：7/16 次调用、4 条路径。管线接受且人工内容保真通过 3/4；严格完整验收为 2/4，另外一条中文技术稿未将两项独立约束分开列点，一条英文稿遗漏末尾请求而被新守卫拒绝。邮件在两个案例中形成了自然段落，技术请求遗漏得以阻断，但不能声称所有场景已经优化完成。详细源码、原生复验、构建和已知边界统一见[本版报告](../experiments/scene-aware-dictation-0.2.22-2026-10-15.md)。
