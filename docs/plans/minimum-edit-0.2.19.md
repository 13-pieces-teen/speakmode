# 0.2.19：统一微整理与受限语言修复

目标是完整保留意思，同时清掉口头卡顿、接好被识别断句切开的句子，修复局部语病。Mode 控制布局，不能成为保真程度档位。现有正常交付、原稿保底、手动候选审阅及取消契约保留。

| 0.2.18 | 本轮增量 | 验证 |
| --- | --- | --- |
| 默认自动用流畅协议，其他 Mode 用旧协议 | 自动、轻整理、结构、自定义采用同一基础清理，布局规则单独输入 | 同源不同 Mode、个人规则及冲突规则 |
| 复核拒绝只回退 | 仅清理项失败且其他四项通过、问题唯一可定位时，最多一次局部替换，再重新全文复核 | 不改问题范围以外文本、原稿/Mode/草稿身份、取消与期限 |
| 整体检查可能漏掉不自然表达 | 在复核中具体检查残句、搭配和过度改写；同时记录保真与可读性 | 成稿人工逐条审阅，不把模型接受当作正确证明 |

默认支持范围限定为本轮验证的百炼北京 `qwen3.8-flash`；其他模型沿用当前流程，不能因可选择就宣称质量经过验证。最终选择 `minimum-edit-v3 + minimum-review-v3 + residue-hint-v2 + local-repair-v2`，有限接入日常链路；不宣称通用质量达标。

共同绝对期限仍为短文 5 秒、中等 8 秒、长文 20 秒。生成、复核、最多一次局部修复及必要的新复核共享期限；无追加等待、循环重试或打开主面板。失败返回完整识别稿；取消/来源失效不输入。手动候选与 Mode 试用只生成一次，最终仍由用户编辑并确认，不能据此授权自动输入。

实验发现模型会漏看明显卡顿，且正确局部清理可能被最后一次复核的耗时挡住。追加很窄的本地提示：只定位来源唯一对应、无引语/代码的多重卡顿句头，不直接改正文。若修复严格等于删除识别出的重复句头，且其他字符、观点、限定、数量、模式、块身份及来源映射均不变，可以本地验收，正常链路从四次请求减为三次。任何改词、标点、顺序或其他内容的修复仍要新全文复核。这是有限产品规则，不是任意语义等价的形式证明。

## 有限实验预登记

- 固定 16 条同源配对：自动 6、轻整理 3、结构 3、自定义 4；包含真实投诉案例和新合成边界文本。两臂独立请求，保留全部失败。
- 基线为 0.2.18 的实际生成/复核协议，不随着新协议改变。新链路最多 4 次请求；基线自动最多 2 次，其他 Mode 1 次。额外盲序成稿比较最多 16 次，总上限 112 次。不重试，不在失败后换材料。
- 记录保真（有效事项、数字归属、条件/否定/不确定性）、可读性、过度改写、布局及交付等待。不同模型的盲序评价是辅助证据，不能等同于独立人工评审。
- 固定文本不包含采音/ASR/跨应用粘贴，不得据此宣称达到 Typeless 的真实语音水平。
- 推广条件：有效保真不退步，可读性改善，原期限内可用结果不退步；若不满足，记录不足，保留旧生产协议。
