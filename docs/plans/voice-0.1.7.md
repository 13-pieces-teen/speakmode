## 本轮增量

| 项目 | 0.1.6 → 0.1.7 | 验收方法 |
| --- | --- | --- |
| O01 局部恢复 | 点击光标不更新旧选区 → 明确捕获光标插入／选区替换；默认不选择整个目标段 | 原生 Store 零长度插入与撤销；生产 React 合成 bridge 中实际选区、emoji、来源收起、目标切换与版本失效检查 |
| O03 成稿入口 | 未确认派发时浮层没有查看入口 → 显式查看成稿，不复制或重发 | 未确认派发、处理中、失败和换代场景；只有主动查看调用 showMain |
| O03 权限说明 | 更高完整性目标检查原因被归为目标不可用 → 保存类型化原因，在成稿完成后记录一次 Skipped 回执并显示手动粘贴说明 | stop anchor／目标 inspection 两种失败、迟到错误、账本与重复 stop／交付回归；不自动提权 |
| O02 结束诊断 | 仅阶段耗时／队列峰值 → 分层帧样本计数、实际 socket 写出时间、Finish 和最终段落状态 | 本地协议与非阻塞／隐私回归；显式固定音频真实云实验。入队、写出和服务端事件分开，不把 send 当 ACK |
| O02 缓存重试 | 不等配置 ACK、突发回放整段 → 等配置 ACK 后按 16 kHz 实际音频时长逐帧回放；通道阻塞不积攒补发额度，取消／ASR 结束释放 producer | 配置等待、真实样本／补零／Finish、背压节拍与取消回归；真实生产 retry 的冻结 B/C 实验；代价是重试等待约音频长度，不宣称加速 |
| O03 原生验收工具 | 前台激活失败与产品路径混在总失败中 → 标准自有进程前台许可交接、明确阶段和失败分类 | 自有 Edit／RichEdit 输入和目标改变／只读／密码拒绝；正常 Windows 前台策略拒绝时如实记录，不用强拉焦点或模拟 Alt |

保持现有雾白界面、右 Alt 开始／结束、Mode、流式字幕和真实波形。保持来源覆盖、严格 final 完整性检查、版本仲裁、局部恢复、撤销及一次性输入。未更改模型、地域、VAD 或麦克风参数。初始实验实际写出全部音频，但 burst B/C 分别仅识别“文。”／“第一项。”，据此增加缓存回放节拍修复；这不是历史实时 `asr_incomplete` 根因证明。官方 Qwen 文件输入示例也按 100 ms 的 PCM 帧间隔模拟实时发送，见[百炼实时语音识别示例](https://help.aliyun.com/zh/model-studio/real-time-speech-recognition-user-guide)。
