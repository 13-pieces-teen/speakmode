# SpeakMode 0.2.3：统一标题字体与明确用量范围

2026-10-09。基线为已合并的 0.2.2（`c658678`，PR #3），本版桌面版本 0.2.3、前端版本 0.4.3。延续现有雾白界面、卡片、顶部用量和 Mode 交互，不调整语音模型或自动输入链路。

## 问题与判断

标题并非只存在字号差异：随程序分发的 `speakmode-sans.woff2` 是仅含 553 个字符的 Noto Sans SC 子集，同一句中文会逐字混用本地字体与系统回退字体。旧标题还分别使用 500、550、600、650 等字重，放大了不一致。

用量此前已由 SQLite 的 `usage_events` 持久化，不是页面内存计数。首页只显示当天数据，跨日后正确归零，却没有具体日期和累计入口，容易被理解为重启丢失。旧界面的默认零值也不能清楚区分“今天没有口述”和“尚未读到统计”。用户确认保留今日默认视图，并增加累计切换。

## 本版增量

| 场景 | 0.2.2 | 0.2.3 | 验收方法 |
| --- | --- | --- | --- |
| 中文标题 | 子集字体与系统字体逐字混排，标题字重不一致 | 本地字体仅用于拉丁字符，中文采用统一系统字体；共享标题字重 600，保留字号层级 | Edge CDP 逐字检查实际平台字体，覆盖原字体缺字 |
| 首页用量范围 | 只有今日，无日期或累计入口 | 默认今日，展示本机日期；可切换此设备累计次数、字数、时长 | 合成多日用量、真实 SQLite 重开测试 |
| 读取状态 | 默认零值可能被理解为已读结果 | 首次读取显示占位；失败可重试，同范围刷新失败保留旧值并说明 | 延迟、失败、重试与乱序请求 |
| 跨日刷新 | 首页长期打开时日期含义不明确 | 窗口重新激活、可见性变化及可见页面定时检查日期；迟到响应不得串日 | 午夜前后旧日／新日响应两种分支 |
| 累计读取 | 无 UI 入口 | 新增只读 `usage.total`；按已有账本汇总，不由前端累加 | IPC 权限、camelCase 契约、无 changed 事件 |

## 统计契约

- `usage.today` 与原 snapshot 的今日统计契约保持；新增 `usage.total` 返回 `count`、`sourceCharCount`、`captureDurationMs`。
- 字数仍来自识别稿的既有字符计数规则，界面标签为“口述字数”，不把它描述为最终整理稿字数。
- 修改、复制、重新整理或删除历史记录不重新计数，也不扣减累计用量。关闭历史保存后，不含正文的用量记录依旧遵循原有持久化规则。
- 不新增 schema 迁移，不从现存历史正文反推或补造旧用量，不读取个人口述内容作为测试素材。
- “此设备累计”是当前资料目录的用量；本版不新增账号同步、云端统计或跨资料目录合并。

## 交付要求

运行 TypeScript／Vite、新增字体与用量浏览器检查、既有 UI 回归及 Windows desktop 库测试，再构建独立程序和 NSIS。浏览器合成 bridge 只能证明前端表现；数据库重开测试才用于验证持久化路径。测试、构建及真实安装启动分别记录，实际状态见[验证报告](../experiments/ui-0.2.3-2026-10-09.md)。
