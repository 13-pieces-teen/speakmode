# 0.2.17 听写链路升级

日期 2026-10-12；接续长口述候选调查，目标是交付可测试的 Windows 程序。

## 实施与验收

1. 引语/代码保护：生成前可逆隔离，恢复后本地逐字及数量检查。模型接受也不能放行被删改的引语。保留原始识别来源、来源/Mode 哈希与一次交付。
2. 长文：默认自动的 400 字以上且以中文为主的来源使用短标记全文整理，保持整体流程与内部步骤、跨 ASR 分片接句、有效细节。400 字以内维持短流程；400 字以内 5 秒、401–800 字 8 秒、更长 20 秒，两次请求共享截止时间。
3. 词典：小写词条也可匹配；同一字母序列的大小写、普通空格和分开读出的缩写可规范。引语、代码、地址及字面标识符不替换，不使用无证据的同音/模糊匹配。
4. ASR：固定音频分别对比旧识别与已接入的 Audio 3.1，词典开/关各一次；根据测量决定默认推荐。当前会话保存词库版本、词数、能力和配置写入 socket 的元数据，不能把请求写入当作服务已采用或识别质量证明。
5. 测试覆盖逐字引语、代码、混合专业词、3 外层/2 内层、否定/条件/改口、取消、超时、单次交付以及旧路径兼容。前一轮已曝光案例作为回归；新合成例为本轮开发验证，不称独立盲测。

## 有限实验与发行

本轮至多 32 次服务调用：先 4 次固定音频识别，再有限完整生成/核对。原始音频与云端文本收据保留在仓库外；失败不重生成挑最好。现有用户配置仅为实验读取，安装包构建不更改或重启用户应用。发行文件复用原有安装资料，由用户启动测试；若采用新默认，启动时的配置升级应仅覆盖确切旧默认且记录一次，尊重后续用户选择。

验收看最终可交付文本、语气词、遗漏/新增、术语与引语，以及整条等待时间。原生录音/跨应用输入留给用户测试，构建成功不代表该项完成。
