# 英文自然成稿与明确整理要求

本轮从 `ca82a93` 开始，判断同一份中英混合来源能否在保留事实、时态和不确定性的前提下，减少英文成稿需要的人工修改。沿用已确认的 11 个用户识别片段；没有找到对应原音频，所以本轮不声称 ASR 或完整真人任务改善。

## 实施边界

1. 统一自动模式、自定义和内置场合的显式英文候选请求，使生成/复核得到一致的来源、语言、格式要求和保真合同。用户确认只作用于已绑定的精确范围。
2. 对有限的英语时态关系和跨识别边界年份做可定位的保护与辅助提示，特别是跨行主谓、不同对象的时态互换和与年份无关的改口词。保留独立复核、未知词不猜、全部原稿及既有期限；不增加模型调用。
3. 使用现有自定义场合的组织方式和规则，明确提供自然段/独立约束分点模板。模板是用户选择的整理要求，口述中的请求仍属于正文；不做自动命令删除，不将排版要求伪装为识别纠错。
4. 保留原始来源、历史版本、撤销、一次投递与上下文读取边界。本轮不修改运行实例、真实词库或历史，不安装程序。

## 实验预登记

- 独立总上限 **32 次请求**。英文配对 6 个案例 × 2 臂 × 最多 2 次 = 24；明确格式要求 4 条路径 × 最多 2 次 = 8。旧账本不重开，不自动重试不明网络结果，鉴权/限流立即停止。
- 两个私有案例为同一自我介绍的“仅英语目标”和“英语加三项已有确认”。它们不是两个独立用户，也不能把确认带来的信息增益算成提示词能力。其余四个是首次请求前冻结的合成样例。
- 每对使用同一来源、确认范围、模式、规则、语言、服务商、模型和 20 秒候选期限。基线使用改动前生产代码；候选在检查两臂响应前冻结。新 fixture 哈希记录于本机 `experiment-plan.json`。
- 排版实验使用两种来源分别选择自然段和分点，检验模板执行、条件归属和正文请求保留；不宣称自动判断用户操作意图。
- 每条分别评估：候选是否返回、复核是否通过、事实/条件/时态是否完整、未知名称是否猜改、实质中文是否丢失、卡顿及段落是否达到可用程度。模型 accept 或本地检查阴性都不是完整成功。
- 独立审阅新结果，保留失败。没有原音频和真人操作，故 ASR 词错率、真实人工修改次数和完整任务耗时均为 NOT_RUN；仅报告成稿路径耗时及文本质量。

## 推广条件

协议一致性与确定性保护需通过真实代码路径回归。文案/模板需通过生产 React 合成交互检查。模型改动根据配对结果决定是否采用；未证明收益时保留实验结果与有效工程修复，不宣称完成所有场景优化。最终生成源码 PR，并给出实际验证范围。

## 本轮收尾

已完成实现、代码冻结、843 项通过的 Rust 回归、12 项通过的生产 React 合成交互、30/32 次有限请求及 0.2.23 EXE/NSIS 构建。完整文本路径 2/6 → 4/6，明确排版 4/4；仍有未确认术语与双语否定状态检查问题。预算关闭，不用余量针对同一批新响应调参。详见[结果与下一目标](../experiments/bilingual-task-quality-0.2.23-2026-10-17.md)；真人录音及实际宿主完整任务仍为 NOT_RUN。
