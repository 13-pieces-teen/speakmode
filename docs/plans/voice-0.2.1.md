# SpeakMode 0.2.1：失败恢复与词典容量

2026-10-09。基线为已合并的 0.2.0（PR #1；`de2b6d0`）。保持 Windows 云端听写、现有 Mode、来源对照和撤销；本轮不更换默认模型，也不把可靠性修复描述为识别准确率提升。

| 改进 | 0.2.0 问题 | 本轮目标 | 验收方式 |
| --- | --- | --- | --- |
| 到期释放音频 | 30 分钟后禁用重试，缓存本身仍存在 | 到原期限主动释放 PCM，不依赖打开页面；不得重新延长期限 | 合成 PCM，短期限定时器与快照兜底，确认缓存释放 |
| 独立失败恢复 | 开始下一条直接覆盖唯一活动会话 | 额外保留一条完整、可重试的失败录音；主面板可打开或明确放弃 | 下一条录音前后身份、原期限、资源准入、容量、取消及旧事件隔离 |
| 词典容量预判 | 仅显示条数／字符数，超出编码容量后才由服务端报错 | 显示已保存词典的实际 UTF-8 编码字节，编辑／导入显示合并前上限 | 中文、emoji、转义字符、修改已有词条、边界值与重复词 |
| 发送中操作一致性 | 主面板在 Prepared／Dispatched 时仍出现查看按钮 | 遵循现有交付状态，发送完成前不提供竞争操作 | 生产 React 合成 bridge；终态仍能查看成稿 |

恢复槽只存在于进程内存中，保持原来的 30 分钟上限。不会写入音频文件或个人历史，不自动重新请求云端；用户打开恢复后，再明确点击「重试识别」。重试完成先查看结果，不补发到原来的输入框。已有槽不能被无声替换，保存失败也不能因开始新录音而被覆盖。到期、明确放弃、锁屏／退出应清理对应缓存。

前端只从权威快照接纳已退休会话的新 generation，迟到的 session 事件不能让旧录音回到界面。录音浮层不接收恢复槽正文。当前口述尚未释放资源时，恢复入口展示原因并禁用打开操作。

容量提示按当前产品 `常用词汇：` 加 JSON 数组的编码计算；空词典为零。草稿显示合并前上限，后端的 Unicode casefold 去重与事务容量校验仍是最终依据。不通过前端估值禁止用户提交可能被后端正确去重的词条。本轮不增加原生 dry-run 接口。

完整剪贴板事务回滚继续保留在 O10：现有代码已在复制前检查目标／修饰键，且先分配内存再清空剪贴板；复制之后因目标变化而跳过派发时仍可能改变剪贴板，不能宣称本轮解决。真实宿主输入、真人听写、安装升级继续与合成回归分开验收。

实际执行与结果见本版实验记录，失败日志保留。本轮无需运行真实云端质量矩阵，原有 0.2.0 模型结论不变。
