# SpeakMode：下一轮优化清单

维护日期：2026-10-08。比较基线：桌面 **0.1.6**，产品候选 `779fa56ea3acb6bc923c552b1eb9269370dc9cd0`，本次只读排查时仓库 HEAD 为 `980f5c4f4790e945e54bb3feac0780b709cd1053`。

本清单来自 0.1.6 实现、并行代码审查和[0.1.6 真实复测](../experiments/voice-repair-0.1.6-2026-10-08.md)。原排查为只读；随后按[0.1.7 计划](voice-0.1.7.md)实施 O01、O03 和 O02 诊断／缓存重试修复。下面“现状／证据”保留原 0.1.6 基线，当前状态以优先顺序表及版本报告为准。O04–O10 仍为建议，不写成已交付功能。

## 产品目标与基线

产品目标仍是：右 Alt 开始／结束，允许停顿和翻阅资料；流式字幕供参考，结束后按 Mode 整理并尝试一次输入；发现改错后能局部修正，保留其他正确整理。保持当前雾白风格、Auto／轻整理／结构／个人 Mode，以及识别稿、局部恢复和撤销。

当前已具备真实 RMS 波形、词典、个人 Mode 文本试用、阶段提示、来源全覆盖检查、有限中文限定检查、失败重试和一次性输入仲裁。以下建议是在这些能力上的增量，不重复立项。

| 基线证据 | 当前结论 | 对下一轮的影响 |
| --- | --- | --- |
| 固定音频主矩阵 11/12 完整 ASR；22/24 整理任务产出，实际整理调用 22/22 接受 | 整理解析明显改善，但整批目标仍未达成；一次 `asr_incomplete` 根因开放 | 先定位缺尾句，保留原失败；单独复测成功不能代替修复证据 |
| 22 个实际成稿都用一个正文块对应全部来源 | 来源完整覆盖已成立，精确逐 bullet 映射尚未成立 | 不能把颜色或粗映射宣传成语义判断；恢复要支持精确字符选择 |
| 自有 Windows 输入首轮 4/8、独立复跑 0/8，失败发生在测试窗口前台激活阶段 | 本轮正向输入未验收；这些失败不能直接归因产品输入路径 | 优先建立稳定的真实宿主验收，再改对应产品问题 |
| 实际整理调用中位数 649 ms，样本 22 次 | 小样本顺序实验，不能推断日常总等待、总体 P95 或全部提速归因 | 后续分别测首可见字幕、stop→Ready、Ready→派发及自有宿主读回 |

## O01：恢复到光标，而不是旧选区

- **现状／证据：** [HistoryDetail.tsx:43](../../app/src/components/HistoryDetail.tsx#L43) 选择结果段后默认范围是整段；[目标文本 onSelect:66](../../app/src/components/HistoryDetail.tsx#L66) 只同步非空选区，收起选区成为光标时仍保留之前范围。[store.rs:518](../../app/src-tauri/src/core/store.rs#L518) 的后端范围替换已经支持 `start == end` 插入。预览、Unicode 字符范围、版本冲突检查和撤销已有。
- **用户影响：** 想补回“今天”或“不”，仅点击目标位置不能正确表达插入；预览可能仍显示整段或旧范围被替换。此结论来自静态代码，尚未进行桌面／浏览器复现。
- **改进：** 目标范围始终同步，包含零长度光标；切换结果段清除旧目标意图，要求明确选位置；预览标明“插入”或“替换”。来源选区也应在收起时同步为空，暂停恢复按钮，避免沿用旧来源选区。继续保留确认预览和撤销。
- **验收：** 选中来源“今天”，在结果指定位置插入，其他字符完全不变；先选整段再收起到光标、跨段切换、emoji 前后位置和撤销均正确。记录恢复点击数、耗时和错误替换次数，与当前版同任务比较。
- **边界：** 不自动猜恢复位置，不通过自动重新整理覆盖用户的局部改动。

## O02：先解释那次缺尾句，再决定改哪里

- **现状／证据：** 真实主矩阵 B-off-r2 有一次 `asr_incomplete`：实验入队帧／样本计数完整，收到 `session.finished`，但组装器仍有未 final 的段落，且文本缺少后半条件信息。现有 [diagnostics.rs:12](../../app/src-tauri/src/engine/diagnostics.rs#L12) 主要记录阶段和队列峰值；[asr.rs:260](../../app/src-tauri/src/cloud/asr.rs#L260) 的实际 socket 发送时刻和终止段落状态未进入诊断。入队计数不能证明逐帧 socket 写出，不能据此认定是麦克风、VAD 或服务商故障。
- **改进：** 在现有有界元数据诊断中补采集／入队／实际写出帧数与样本数、最后帧和 Finish 写出时刻、事件类型／顺序、pending／final 数量。优先复用现有手动诊断导出机制；不用另建日志面板，不记录音频、正文或 Key，采音回调不能等待日志锁。
- **协议边界：** socket send 成功只说明客户端写出。官方 `input_audio_buffer.append` 没有逐帧 ACK；VAD 模式不能发送手动 `commit`。当前 0.0／400 ms 已符合官方推荐，不能以盲目增加静音阈值作为修复。[百炼客户端事件](https://help.aliyun.com/zh/model-studio/qwen-asr-realtime-client-events)、[服务端事件](https://help.aliyun.com/zh/model-studio/qwen-asr-realtime-server-events)。
- **另外评估重试：** [生产 retry_asr:681](../../app/src-tauri/src/engine/session.rs#L681) 直接循环回放缓存，现有 [voice_lab:168](../../app/src-tauri/examples/voice_lab.rs#L168) 按音频时长发送。两条路径不同；先通过实际协调器重试路径比较现有回放与受限节拍。突发发送是否影响 final／质量尚无证据，不能一律改成实时速度，让长录音重试等待同样长。
- **验收：** 预登记短、多分钟及含 30 秒停顿的固定 PCM，分别测原始路径和真实重试路径；记录尾句／否定／条件完整性、发送样本一致性、final 收齐、总耗时和取消释放。注入缺帧、Finish 未写出、已写出但 final 缺失的独立场景，验证诊断可区分。根因修复后按同批输入复测，保留每次原失败，不用补跑替换原成绩。
- **停止条件：** 没有根因证据时不放宽 pending 检查、丢掉未 final 来源或自动重复请求来制造成功。

- **改进二：** [deliveryFeedback.ts:25](../../app/src/services/deliveryFeedback.ts#L25) 对 `unconfirmed` 设置 `canCopyOutput=false`，浮层因此没有查看成稿入口；主面板已有入口。给浮层这一状态保留克制的“查看成稿”，进入结果后由用户显式复制；按现有错误分类给出目标改变、快捷键未释放等指引。权限检查已存在，但 [session.rs:218](../../app/src-tauri/src/engine/session.rs#L218) 将目标检查错误丢弃，尚无独立权限原因；需要保留明确分类后再提供对应权限指引。恢复不能自动重发。

## O05：失败后继续录下一条，也能找回上一条

- **现状／证据：** 完整 ASR 失败的音频缓存属于唯一 ActiveSession；[session.rs:183](../../app/src-tauri/src/engine/session.rs#L183) 开始新录音会替换它。[30 分钟检查:76](../../app/src-tauri/src/engine/session.rs#L76) 只限制重试资格，没有主动到期释放计时器。整理失败已有来源检查点；保存失败已有 PendingCommit 与保存重试机制，但来源检查点自身保存失败时尚未提交成功。这些机制不应重复重做。
- **改进：** 保留一个容量受限的失败恢复槽，独立于新录音；显示恢复期限，并在取消／到期主动清除 PCM。沿用内存缓存，不扩大自动持久化录音范围；内存不足或旧失败将被替换时明确告知。
- **验收：** 识别失败→新录音→显式重试旧失败，旧条目仍可在期限内恢复。旧失败重试须等待当前录音／处理释放，沿用资源准入检查，不能替换正在工作的 session。到期确实释放内存；旧 session／generation 不覆盖新内容，重复重试和取消不重复保存或输入。记录恢复保留率、缓存上限和到期清理延迟。
- **边界：** 不承诺重启后保留失败音频，不改正常录音流程，不自动重试或重新粘贴。

## O06：保护最终金额，识别“改口改的是哪一部分”

- **现状／证据：** [rewrite_integrity.rs:154](../../app/src-tauri/src/cloud/rewrite_integrity.rs#L154) 的数字转换用于限定词局部匹配，没有独立最终金额保护；[effective_spans:89](../../app/src-tauri/src/cloud/rewrite_integrity.rs#L89) 的明确改口可撤回整个旧分句。[条件锚点:48](../../app/src-tauri/src/cloud/rewrite_integrity.rs#L48) 与 [作用对象匹配:211](../../app/src-tauri/src/cloud/rewrite_integrity.rs#L211) 还存在有限规则边界。
- **待验证反例：** “预算3500元，不是5000元”→“预算3000元，不是5000元”可能漏拦；“今天预算先五千，不对，是三千五百元”可能使没有更正的“今天”失去保护。“若干选项”→“几个选项”可能误拦；“不要删除原始录音”→“删除原始录音，不要删除测试录音”可能因共享动作词而漏拦。这些是代码路径推导，不是本轮云端或新增测试结果。
- **改进：** 先限定明确金额、货币单位和部分改口，金额纠正只撤回旧金额；增加有限中性词排除及禁止事项的对象限定检查。日期明确纠正仍允许“今天，不对，明天”。有歧义时保留来源供核对。
- **验收：** 先冻结金额、小数、数字格式变化、日期纠正、对象替换和合法同义改写的正反例，再实现。分别统计错误接受、错误拒绝，以及正确接受、正确拒绝，不能只追求调用接受率或拒绝率。指定反例符合预期，既有 guard 回归及 A/B/C 同批云端语义核对保持通过。
- **边界：** 有限中文检查，不宣传一般语义证明；不为提高接受率削弱否定、条件、来源覆盖或恢复能力。

## O09：词典保存前显示真实上下文容量

- **现状／证据：** [dictionary.ts:3](../../app/src/dictionary.ts#L3) 的前端限制为 200 条／每条 80 Unicode 字符；[store.rs:72](../../app/src-tauri/src/core/store.rs#L72) 为 SpeakMode 自设的完整序列化 ASR context 设置 4000 UTF-8 bytes 上限，未核实为服务商硬上限。非空词库计入“常用词汇：”的 15 bytes 和 JSON 数组的括号、引号、逗号及必要转义；空词库不提交 context。UI 已有总容量超限说明，但没有实时、数值化预判，用户仍可能提交后才知道失败。
- **改进：** 复用后端标准化与序列化逻辑进行只读草稿校验，显示保存后的上下文预算；超限前提示需缩短容量。保留原拼写、去重、版本冲突和下一次录音生效规则，不自动截断。

- **边界：** 容量合格不保证专有词一定正确；不自动学习用户历史、不把词典变成强制替换表。

## O10：缩小剪贴板副作用

- **现状／证据：** [delivery.rs:457](../../app/src-tauri/src/platform/delivery.rs#L457) 清空并写入 Unicode 文本，后续目标检查或按键检查仍可能拒绝派发；当前没有旧剪贴板恢复。用户可能没有获得自动输入，但原复制内容已被替换。
- **改进顺序：** 先解决确定没有派发的失败分支：在明确支持的文本格式范围内保存旧内容，失败时仅在剪贴板仍由本次写入拥有的条件下恢复。序列核对与恢复在同一次成功 OpenClipboard 的临界区内完成，用户后来主动复制的内容不得被覆盖。若存在无法保留的未知格式，不能只备份 Unicode 然后宣称可完整恢复；采用保留原剪贴板并提示显式复制的路径，交互变化单独验收。
- **验收：** 写入后目标改变／取消／修饰键超时且未派发，旧文本可恢复；期间用户新复制内容保持，包括序列检查与恢复之间的并发复制竞态；锁定、空剪贴板、非文本格式行为明确，不触发再次输入。
- **边界／暂停项：** 成功派发后宿主读取时间不可泛化确认，不能盲用固定定时器还原。HTML、图片和 OLE 全格式恢复成本更高，暂不作为 MVP 承诺；若无法可靠保留格式，只提供明确行为，不发布“完全不影响剪贴板”的结论。

## 增量评估与实施拆分

每项实施前冻结基线代码、输入、评分规则和调用顺序；实施后保留首次结果及全部失败，单独记录诊断复跑。指标分为：

| 目标 | 可比较指标 | 证据边界 |
| --- | --- | --- |
| 语音流畅 | 首 PCM→首可见字幕；stop→ASR 完成→Ready；取消／停止释放时间 | 原生与渲染时间分别测；发送入队不冒充实际写出 |
| 整理得当 | 尾句、条件、否定、金额等指定事实完整性；错误接受、错误拒绝及两类正确判断；Mode 格式满足率 | 固定音频／文字实验和真人口述分别报告；无一般语义保证 |
| 交付可靠 | 自有宿主正确位置读回率、重复输入次数、Ready→派发时间 | fixture 前置失败单列；产品派发状态不冒充真实插入确认 |
| 原意可修复 | 发现遗漏率、局部恢复成功率、耗时、点击数及误替换数 | 离线回归证明功能；5–8 名参与者的形成性对照只支持该任务范围 |
| 故障可恢复 | 失败缓存保留／到期释放、正确下一步操作率、无效重试和无效词典保存次数 | 设备故障注入与真实设备分别报告，不虚构总体稳定性提升 |

建议拆为三批，不在同一次改动中混合调模型、音频参数和界面：

1. **恢复与交付：** O01；O03 的成稿入口和真实宿主验收。可直接核对“只恢复选定内容、一次输入、失败可找回”。
2. **采音与结束链路：** O02 的诊断和实际重试实验；依据结果做根因修复，再 O04／O05。不得为稳定性假设先重写 ASR。
3. **保真与易用性：** O06 先冻结反例，再实施；O07／O08／O09 单独比较交互成本。O10 在所有权与格式边界明确后再推进。

本清单的所有提升均为**待实施／待测量**；当前 0.1.6 已有成绩继续以验证记录和原始收据为准。
