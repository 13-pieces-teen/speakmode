# 0.2.14：修复微整理结果被误退回原稿

日期：2026-10-11。基线为桌面 0.2.13 / 前端 0.4.12。

## 已确认的问题

用户本轮短口述中，停顿词和重复起头仍出现在最终文本。只读核对运行程序及最新来源，确认运行的是已发布 0.2.13，最新来源忽略标点和空白与用户提供的文本匹配，记录的回退原因是 `meaningRisk`，不是超时。数据库没有保存被拒绝的模型响应，不能反推当次具体触发项。

使用用户主动提供的原文新增两次云端请求：生产提示与已有实验提示各一次，均使用当前 Qwen 3.8 Flash。两份响应已经去除了无意义停顿词；以发布版 0.2.13 校验器离线重判，均因数量检查拒绝。输入中三个口语“一个”被视为必须保留的数量，是这次复现的明确阻塞点。原始请求、失败和文本仅保存在仓库外。

## 实施范围

只修复有限数量校验：识别相邻停顿导致的同一名词短语重启，以及明确描述所属对象效果、实际情况、状态、表现的泛指构式。新豁免必须同时检查候选对应来源、所属对象及局部描述语境，不能只凭源文出现属性词就放行。

保留真正计数、唯一/每个/范围限制、另一对象对比、创建/选择/删除/切换对象、完整复合名词、引用和代码的保护；限定词不能因 ASR 分片或停顿句号而失效。允许的词形与边界通过公开合成正反例固定，不把个人原文写入源码或公开语料。

保持生产提示、模型、等待预算、原始来源、完整原稿回退和一次性输入流程。不会在本轮添加额外模型调用、自动重试或全局机械删词，也不会自动打开主面板。

## 验证与选择

- 本轮云端调用上限两次，已完成；不挑选重生成结果。接下来复用同一响应做离线前后对照，输出与原耗时必须逐项保持一致。
- 两份生成结果及原稿去重后隐藏实验身份，由独立 Agent 按信息、清理、可读性、语气、专名五维检查；完整保真先于文字更短。不把间接疑问使用句号机械判为意义改变。
- 新规则先运行失败测试，随后检查允许与禁止边界；完整 Rust 回归、固定守卫探针及已知旧 Mode 回归必须执行。已有两个旧缺口须继续列明，不宣称全部语义校验已解决。
- 对上一版保留的 68 个响应离线重判，确认新增接受是否带来已知错误；这不是新云端实验或新的独立预留集。
- 构建带明确版本的 EXE / NSIS，检查复制哈希及构建输入。应用和安装器由用户启动，不中断正在进行的口述，不写真实用户资料。

## 效果边界

本轮目标是让已成功清理的响应通过正确的校验，减少退回带语气词原稿的情况。两次文字请求不能证明 ASR 准确率、日常所有口述或与 Typeless 同音频的整体差距已经改善；真实录音、跨应用输入与安装升级另由用户验收。

## 完成记录

已完成两次云请求、同响应修复前后离线重判和独立正文盲评；两份结果由拒绝变为接受，没有重生成或更改原耗时。新增规则最终覆盖 9 个正例、41 个反例，完整 Rust 661 项通过；审阅中发现的相反动作并列、名称内动词和跨暂停短限定三类问题均保留 RED→GREEN 记录。
