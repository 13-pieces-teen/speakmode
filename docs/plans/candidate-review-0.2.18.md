# 0.2.18：可编辑的候选审阅

用户需要直接看见整理前后的改动，并决定是否保留。原实现把历史候选与自动交付共用保真拦截；遇到数字、条件或引语变化时只显示红色错误，没有可核对的正文。此版将显式的历史候选变成可操作的草稿。

| 0.2.17 行为 | 0.2.18 行为 | 验收依据 |
| --- | --- | --- |
| 合法候选仍可能因保真检查被整体拒绝 | 返回草稿与有限核对提示，保存需要用户明确选择 | 同一数字／否定／引语变化样例，自动路径仍拒绝，手动路径可展示 |
| 对照需要展开，只能整体采用 | 默认展示划线与蓝色标记，逐处保留或采用，可直接编辑 | Unicode 内容重建、局部选择、手动编辑与保存 |
| 保存只能采用服务端原候选 | 将用户最终文本与冻结的候选身份、来源和基线一起核对后提交 | 精确保存、来源不可伪造、版本冲突、取消与撤销 |
| 候选与当前版本编辑可以交错 | 审阅期间只开放候选编辑，外部版本更新后保留草稿但禁止覆盖 | 并发修改与草稿离开保护 |

## 实现

- `rewrite_manual_candidate.rs` 只用于主面板的 `history.rewrite`。沿用配置的模型与任务；默认自动使用流畅／长文生成，其他模式使用原模式协议。每次显式生成发出一次请求，20 秒绝对期限，不重试，不要求自动交付核对器放行。
- 响应仍须完整结束、符合 JSON、容量、模式和完整来源映射契约。结构无效、来源不完整、超时、取消与网络错误不能冒充有效候选。数字／限定／引语检查结果作为瞬态 `reviewIssues` 返回，不写成模型准确率或语义正确证明。
- `CandidateComparison` 保留雾白、蓝色与 Radix 组件，默认显示行内对照。暖色划线表示被删改的文字，蓝色下划线表示新增；小按钮支持鼠标和键盘切换。标记本身也可以点击。
- 差异计算设定输入、编辑数量、耗时和选择数量上限，超限完整展示两份文本并明确按整段处理。不截断正文，不把字符对应当成识别来源对应。
- `revision.adopt` 增加 `reviewedText`，仅接受现存、未取消、基线未改变的候选。人工改动后的全文绑定该候选已有的完整来源集合，不接受前端自造来源。空文本、空字符或八万字超限拒绝；新版本保存和撤销走原数据库事务。
- 核对提示只说明生成稿需要检查，用户可继续编辑。保存前不改变当前文本；取消与离开放弃只清理候选。保存不会粘贴到其他应用或改变新口述默认 Mode。

## 范围

本版不修改正常右 Alt 听写的自动交付条件、模型默认值、识别链路或原稿保底。人工选择不是自动保真的证据。无数据库迁移；候选正文只在本次运行内保留，明确保存后才成为历史版本。
